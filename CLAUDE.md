# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Scirè** — cross-platform (macOS + Linux) desktop music client for [Navidrome](https://www.navidrome.org/) servers and local music files, built with GPUI (Zed's UI framework) + [gpui-component](https://github.com/longbridge/gpui-component). Speaks Subsonic API v1.16.1 + OpenSubsonic; identifies as `scire` in the Subsonic `c` param. Local music support: engine reads local files via `SourceReader::Local(File)`, album grid UI with cover art (DB cached via `scan_version` counter), album detail view with track listing (`LocalAlbumDetailView`), incremental mtime-based scanner, periodic background scan (5 min). See `README.md` for the user-facing feature list and Linux build deps.

## Commands

```bash
cargo run                     # build + launch the app (crates/app binary)
cargo test --workspace        # all tests
cargo test -p subsonic        # API client tests only (fast, no gpui build)
cargo test -p playback        # playback engine test (plays a WAV via local mock HTTP)
cargo test <name>             # tests matching <name>
cargo clippy --workspace --all-targets
cargo fmt --all
```

## Architecture

Cargo workspace, three crates with a strict dependency direction — UI → services → protocol:

- **`crates/subsonic`** — pure async Subsonic/OpenSubsonic API client. reqwest + serde only; NO gpui, NO audio. Every request carries fresh token auth (`t = md5(password+salt)`, new salt per request, built in `auth.rs`). `client.rs` owns the request core + `subsonic-response` envelope unwrapping + typed error codes (40 = bad credentials, 50 = not authorized). Endpoint methods live in `endpoints/{system,browsing,lists,media,playlists,annotation,radio}.rs`. `system.rs` also carries `start_scan()`/`get_scan_status()` → `ScanStatus { scanning, count }`, behind Settings → Library → *Scan server library*; Navidrome restricts `startScan` to admins, so a failure means "the server won't rescan for us" and is reported, not fatal. All catalog methods accept `music_folder_id: Option<&LibraryId>` (multi-library, wired to UI in M3). `stream_url()`/`cover_art_url()` build authenticated URLs without issuing requests — playback/artwork layers fetch them. `Song` struct has an optional `local_path: Option<String>` field (serde-skipped when `None`) for local file tracks.
- **`crates/playback`** — audio engine behind a command/event facade (`Player` handle ↔ `Event` stream via tokio mpsc). Internals: rodio 0.22 (`DeviceSinkBuilder`/`MixerDeviceSink`/`Player` — note rodio renamed Sink→Player in 0.22) + stream-download (HTTP → blocking `Read+Seek` with ranged re-requests for seek). `TrackSource` supports both HTTP streaming and local files via `SourceReader` enum (`Http(StreamDownload)` / `Local(File)`). When `TrackSource.path` is `Some`, `source::open_local()` opens the file directly — no network round-trip. The facade hides rodio completely so the engine can be swapped. Must be constructed inside a tokio runtime context. **Gapless**: one `rodio::Player` lives across tracks; `PrefetchNext` prepares the next decoder, and the engine appends it into that player's queue only once the current track is within `COMMIT_LEAD` (3s) of its end — rodio then hands over sample-continuously. An appended track cannot be withdrawn (rodio's queue has no removal), which is why the commit is deliberately late; `TrackEnded { auto_advanced, started }` reports the id that actually started so the consumer can resync if the queue changed inside that window. The hand-over instant comes from the `EndSignal` source wrapper (`source.rs`), not from polling `Player::empty()`. Also exports `spectrum` — the real-time visualizer feed: a `Tap<S>` source wrapper (same shape as `EndSignal`, inserted in `engine::append` so every track flows through it) mirrors output samples, downmixed to mono, into a lock-free `SpectrumTap` ring (`AtomicU32` bit patterns behind a monotonic write counter — the audio thread never locks); `spectrum::analyze` windows 4096 samples, runs a hand-rolled radix-2 FFT (no FFT dependency) and reduces it to log-spaced bands. `Player::spectrum_tap()` hands the ring to consumers; an unchanged write counter means no audio flowed, so consumers decay instead of freezing. Also exports `waveform::peaks_from_bytes` — offline decode of a full track into normalized RMS loudness buckets (gamma-expanded so compressed masters stay readable); pure CPU, call from a blocking context.
- **`crates/app`** — the gpui binary (package name `scire`). Layers:
  - `services/runtime.rs` — the gpui↔tokio bridge: global 2-worker tokio runtime; `spawn_io(fut)` spawns there and returns a runtime-agnostic future awaited from gpui tasks; `enter(f)` for constructing tokio-dependent types (the playback engine). **Only two workers, so blocking work must go to `spawn_blocking_io(closure)`** (the local scanner, whole-track decodes) — a closure that never yields pins a worker for its whole run and every HTTP request behind it waits, which is how a long local scan used to stall the album grid's first page. Note also that gpui tasks (`cx.spawn`) have no tokio reactor in scope: `tokio::time::sleep` panics there, use `cx.background_executor().timer()`. `services/artwork.rs` — cover-art fetch + disk cache. **Navidrome quirk**: every song gets its own `coverArt` id (`mf-<songId>_<hash>`) even within one album, so caching or change-detecting on it re-downloads identical album art for every track. `song_cover(&Song)` returns `(cover id to request, album-scoped cache key)` and `fetch_as`/`cached` take that key — use them for anything rendering a *song's* cover (player bar, fullscreen, adaptive accent, recent, search). Album/artist covers already carry stable ids and use plain `fetch`; `services/waveform.rs` — seek-bar peaks: downloads a low-bitrate transcode (amplitude envelope survives lossy compression), reduces it via `playback::waveform` to 480 buckets, caches JSON on disk keyed by song id (`.v3` cache version suffix — bump it when the bucket format changes). `PlayerState::prewarm_next_waveform` (fired from `refresh_prefetch`, gated on the `waveform_seekbar` setting mirrored into `waveform_enabled`) computes the *next* track's peaks during the current one, so the bar draws instantly on the hand-over; `fetch_peaks` holds a per-song-id lock so a prewarm and the view asking for the same peaks never both download and decode. `services/library_db.rs` — SQLite music library database (`~/.cache/scire/music.db`) with `tracks`, `albums`, `artists`, `config` tables and simple integer migration (`_schema_version`, currently 4 — v4 adds the source/`album_id` indexes; without `idx_tracks_album` the per-album track count in `album_fingerprints` is a full scan of the track table *per album*, ~2.3s over 1126 albums). Thread-safe via `Mutex<Connection>`. **Write in batches**: SQLite autocommits per statement, so `upsert_catalog` wraps the album/artist rewrite in one transaction — a thousand single upserts was seconds of an otherwise sub-second sync. `services/local_library.rs` — synchronous directory scanner using `lofty` for tag reading; walks `local_music_dirs`, extracts folders (`folder.jpg` / embedded art), upserts tracks/albums/artists into `LibraryDb`. Progress atomics (`AtomicU8` status, `AtomicUsize` count), plus a process-global `SCAN_IN_FLIGHT` — the 5-minute background rescan and the manual refresh each build their own `LocalScanner`, so a per-instance flag doesn't see the other one and the two walks fought over the SQLite write lock with half-filled `seen` sets; a second `scan` while one runs returns `Ok(())` without scanning, so its tests must serialise on the module's `SCAN_TESTS` mutex or they see IDLE. `services/navidrome_sync.rs` — reconciles the Navidrome catalog into `LibraryDb` with source=`navidrome`. Three phases: **list** every album (paginated `getAlbumList2`), **reconcile** against the cache, then **fetch tracks** for the albums that need it, `ALBUM_FETCH_CONCURRENCY` (6) `getAlbum` calls at a time via a `JoinSet`.

`SyncMode::Incremental` (everything except the Settings rebuild) is what makes this cheap: the listing already carries each album's `songCount`/`duration`, so `needs_track_fetch` compares them against `LibraryDb::album_fingerprints` and issues a `getAlbum` **only** for albums that are new or have moved. A settled library costs the three listing requests and a local compare; before this every sync was one `getAlbum` per album whether or not anything had changed (~1100 albums took minutes serially, ~17s at concurrency 6, ~1s incrementally). `track_rows` in the fingerprint is `COUNT(*)` rather than the stored `song_count` because a sync interrupted between phases leaves album rows whose tracks never landed, and those must not look complete. Duration is compared with a 1s tolerance — servers round it and it round-trips through an f64 column, and an exact compare re-fetched albums that hadn't changed. The album *row* is always rewritten even when tracks are skipped: `play_count`/`starred` are the Frequent/Starred tabs' sort keys and move without the track list changing. Albums the listing no longer contains are deleted with their tracks, then `prune_orphan_artists` sweeps up. `fetch_album_tracks` clears the album's tracks before re-inserting, since upserts alone would strand rows for songs deleted from the album (the old full wipe covered that implicitly). `SyncMode::Full` wipes first and so finds no fingerprints, making every album stale — the escape hatch for the one thing incremental cannot see, an album re-tagged without its track count or duration moving.

Walks one music folder at a time (`getMusicFolders` first) so every row records the `library_id` it came from — that provenance is what lets the grids seed their cache for a library *subset*. Pagination stops on a short page, and on a page whose head id repeats the previous page's *within the same folder* — a server ignoring `offset` otherwise loops forever, and comparing against the global `seen` set instead would truncate a second library that shares albums with the first. Publishes `SyncProgress` (`total`/`done` atomics) for the UI. Started once per session from `root.rs` behind its own `sync_started` flag (separate from the local scan's — one shared flag meant it never ran for anyone with local dirs configured) and delayed 30s so it doesn't compete with the album grid's own first page. Also exports `run_server_scan` (`startScan` + poll `getScanStatus`), which runs inside the tokio runtime and so can use `tokio::time` directly, unlike the gpui tasks calling it.

**Two different operations, deliberately split.** The sidebar's **Refresh library** row (`RootView::refresh_library`) is the fast, frequent one: local scan (blocking pool) then an incremental reconcile, in sequence because two IO workers can't carry both. It does *not* ask the server to rescan its disk — pairing them made every refresh cost a full server walk, which is minutes. The server rescan lives in **Settings → Library** alongside **Rebuild local cache** (a `SyncMode::Full` sync); both are slow, occasional jobs, both report a status line rather than a bar since neither has a meaningful total, and `startScan` is admin-only on Navidrome so its error 50 is surfaced to the user rather than swallowed. `run_server_scan`'s grace period covers Navidrome reporting `scanning: false` for a moment after accepting the request — an idle reading only counts once the scan has been seen running, or after the grace elapses.

Progress reaches the sidebar as `RefreshStage` (a `root.rs` enum, unit-tested). Workers publish into atomics; `ui::poll_until_done` awaits the job on `cx.background_spawn` and samples them on a gpui timer (shared by the sidebar refresh and both Settings jobs). Only the import stage has a real denominator, so it alone draws a filled bar — the others report a rising count against no total and get a bare track rather than a bar creeping toward a made-up finish. A refresh that finds nothing new never leaves the `Comparing` wording, which is why `Import(_, 0)` reads the same. On completion the catalog views are dropped and the current page redrawn, but only if it is still one of the listings (a detail view opened meanwhile must not be swapped out from under the user).
  - `state/` — gpui Entities and pure logic: `session.rs` (settings, SubsonicClient, connect flow, music-folder list + library selection), `player.rs` (owns the queue/position/volume, consumes playback events — the single audio↔UI touchpoint — and drives scrobbling, prefetch, media keys, radio), `queue.rs` (pure queue model: shuffle/repeat/reorder, unit-tested), `scrobble.rs` (pure threshold state machine, unit-tested), `playlists.rs` + `radio.rs` (shared CRUD state), `media.rs` (souvlaki OS media controls, best-effort). `player.rs` distinguishes library playback (queue + Subsonic stream URLs) from live radio (`play_radio`, external URL, seek disabled). The queue itself is always persisted (`queue.json`); the **position** inside the current track is only kept when `Settings::resume_playback` is on, in its own `resume.json` — separate because it is rewritten as playback runs (once per whole second, from `Event::Position`, plus a forced write on pause) rather than only on queue edits. Saving as it goes rather than at quit is deliberate: a crash or SIGKILL never runs a shutdown hook. On startup the saved position is only taken if it names the same song the restored queue is sitting on, and it is applied as a **pending seek** — the engine can't seek a source it hasn't opened, so the seek waits for that track's first `Playing` event, and is dropped if the user skips to another track first.
  - `ui/` — views; `root.rs` routes login ↔ main layout (sidebar | content | player bar) and hubs navigation events from child views (`cx.subscribe` on `AlbumsEvent`/`ArtistsEvent`/…). Notable views: `search_bar.rs` (global top-right search — debounced `search3` dropdown with cover thumbnails, `/` shortcut, Esc dismiss; there is no search page), `fullscreen_player.rs` (full-window now-playing overlay with blurred-art background), `player_bar.rs` (renders the waveform seek bar with pixel-accurate click seek), `albums.rs` (infinite-scroll grid, responsive cover sizes, persisted sort; **cache-first**: `seed_from_cache` paints the last `navidrome_sync`'s rows from `LibraryDb` on the first frame — including during the pre-connect wait — and `apply_live_page` then *overwrites* those placeholders from the front rather than appending, so the row count and scroll position hold still while live pages stream in; a header spinner reads "Updating from server…" while the cards are stale. every tab except Recent and Random, whose keys (recently *played*, nothing) aren't in the DB — the sync mirrors `created`/`play_count`/`starred` onto each row and the seed re-sorts them with the same `album_cmp` the live merge uses, so the overwrite lines up; rows also carry `library_id`, so a library subset seeds from its own rows instead of being skipped. Rows written before schema v3 have a NULL `library_id` and are skipped under a subset until the next sync), `artists.rs` (**card grid**, same shape as `albums.rs` — round covers, virtualized `uniform_list` over rows, responsive cols, cache-first seed, header spinner; `getArtists`' index buckets are flattened into one alphabetical list since the grid has no letter headings. Covers are fetched from `render` via `ensure_art_for_viewport`, *not* when the list lands: `getArtists` returns the whole library in one response and fetching every cover would stat the disk once per artist on the main thread. Detail view: bio + artist image from `getArtistInfo2`, cached through the shared artwork cache so revisits render without a flash), `album_detail.rs` (header chips summarising the album's files — formats, bitrate *range*, sample rate / bit depth, channels, total size, added date — plus a ReplayGain line and an "About" card holding `getAlbumInfo2`'s notes with a More/Less toggle and MusicBrainz/Last.fm links. `quality_chips`/`replaygain_line` are pure and unit-tested; everything but the bitrate is OpenSubsonic-only, so vanilla servers simply yield fewer chips. `load_info` is gated on `info.is_none()` because `load` re-runs whenever playback enters or leaves the album). Multi-library selection lives in the sidebar as checkboxes; views merge the selected libraries into single sorted lists.
  - **Vi-mode keyboard navigation** — when `settings.vi_mode` is ON, `root.rs`'s key handler routes to `handle_vi_key` and the legacy no-vi shortcuts (space/arrows/`[`/`]` = play/prev/next/nav) are dead; when OFF they work as before. Every content view implements the cursor protocol: a `vi_cursor: Option<usize>` field plus `vi_move(delta, window, cx)` (clamp + scroll focused item into view), `vi_activate(cx)` (Enter — open/play the focused item), `vi_clear(cx)` (hide cursor when the mode turns off). `root.rs` dispatches through `content_vi_move` / `content_vi_activate` / `content_vi_tab` — add every new `Content` variant to all three plus `vi_clear_cursors`. Focus styling lives in `ui/mod.rs`: `focus_glow(cx)` (BoxShadow) + `with_focus_animation(id, el, cx)` (180 ms ease-out glow-in wrapper; per-item id so it replays on each cursor jump); the focused row also gets `border_color(primary)` + `anchor_scroll(Some(anchor))` + `ScrollAnchor::for_handle(handle)` scroll-into-view, which works for flex-wrap/nested rows. The albums grid is the exception — virtualized, so `vi_move` uses `UniformListScrollHandle::scroll_to_item(row, ScrollStrategy::Top)`; uniform_list's `ScrollStrategy` has only Top/Center/Bottom (no FirstVisible). In vi mode `[`/`]` cycle album filter tabs (`vi_tab`, via `select_tab` which persists `settings.album_sort`); in no-vi mode they are nav back/forward. `:` commands (`:newpl <name>`, `:pl add <name>`, `:pl list`, `:q`, `:help`) live in `execute_command`; `set_vi_status` shows transient feedback with a 4 s auto-clear.

`recent.rs` observes `PlayerState`, which calls `cx.notify()` on **every** event including `Event::Position` — so anything it does per notify or per render happens several times a second for as long as the page is open. It therefore gates on a cheap `signature` (list length + head song id, plus whether a client has appeared) before rebuilding, holds a pre-formatted `Row` model instead of re-deriving strings and cloning `Song`s per frame, and draws through `uniform_list`. Any future view that observes the player needs the same treatment.

`RootView` **retains the albums, artists and recent view entities** across navigation (`albums_view` / `artists_view` / `recent_view`) instead of rebuilding them per visit, which refetched the whole listing and reset scroll on every tab switch. They're subscribed to only on first construction (a second subscribe would stack handlers) and dropped by `invalidate_catalog_views` on **disconnect** and library-selection changes — they never reload on their own. On *connect* they're kept and handed the client through `resume_catalog_views` → each view's `client_ready`, because a rebuild there would blank the covers and reset the scroll of the grid the user is already looking at.

Startup order matters: `RootView::new` opens the default page itself (`open_default_page`, via `cx.defer_in`) rather than waiting for the session observer. The observer only fires when the connect *resolves*, so leaving it to do the first navigation left the window empty for a whole network round-trip even though the cached catalog was ready to paint. It stays wired into the observer too, for the pages that only become reachable later.
  - `ui/visualizer.rs` — the 3D audio visualizer behind the fullscreen overlay. gpui exposes no shaders, so scenes are projected in software (world space → perspective divide → `gpui::canvas` + `paint_path`/`paint_quad`) and drawn back-to-front, since there is no depth buffer. Eight scenes (`Scene`): `Terrain` (scrolling spectrum landscape), `Tunnel` (rings receding to a vanishing point), `Sphere` (rotating Fibonacci point cloud), `Scope` (polar oscilloscope — the **only** scene drawing the time domain: `scope_trace` triggers on a rising zero crossing, since an untriggered trace slides by a random phase each frame, and samples directly at `SCOPE_STRIDE` rather than reducing buckets to peaks, which would draw the envelope and stop the ring crossing its own baseline; past traces are kept in a `scope` deque and drawn as outward-drifting echoes, and a starved tap pushes a flat trace so the trails drain; a faint baseline circle gives the displacement something to be read against, and `hot_runs` picks the stretches swinging within `SCOPE_HOT_REL` of *this trace's own* peak and redraws them thick and near-white — an absolute threshold puts the whole waveform over it on a loud passage and the bloom disappears exactly when it should be strongest), `Bloom` (kaleidoscope mandala in screen space — perspective would break the radial symmetry that is the whole point; per-layer petal counts (`BLOOM_LAYER_SECTORS`, deliberately not dividing each other — layers sharing a count lock into one rigid figure however they rotate) with odd sectors reading the spectrum backwards to mirror, a `sin(πu)` lobe window so petals return to the inner circle instead of merging into a lumpy ring, counter-rotating translucent layers, a bass-driven hub closing the hole the inner radius leaves, and beat spokes drawn *under* the petals and stopped short of them), `Warp` (starfield where each star is drawn as the segment it is about to travel, so speed reads as streak length — the shared per-frame `warp_speed` rides energy plus the beat flash; the field rolls slowly (`WARP_ROLL`) so it reads as flight rather than a zoom, and stars fade out over `WARP_NEAR_FADE` before recycling instead of popping at the near plane), `Orb` (wireframe icosphere — bass inflates the radius, treble roughens it via 3D value noise along the normals; the mesh is generated once by `OrbMesh::new` and the whole wireframe is stroked as subpaths of a *single* path, since a thousand-odd separate tessellations per frame is not affordable), `Retro` (PlayStation-era look: deformed low-poly solids tumbling at the camera over a bass-reactive background — flat per-face shading, back-face culling, painter-sorted opaque faces, depth fog, and `SNAP`-quantised screen vertices for the era's jitter). `VisualizerMode` (in `config.rs`, cycled by the fullscreen player's button and persisted) is Off → **Auto** → the eight pinned scenes (`VisualizerMode::SCENES`, which the mini player's scene popover iterates — adding a scene there needs no UI change). In Auto the scene alternates on the music: `OnsetSwitcher` watches spectral flux (rises only, from the *raw* bands — the smoothed ones have the transients filed off) and switches on flux peaks in two stages, because flux peaks on the *run-up* (risers, snare rolls) and firing on the threshold crossing lands before the beat: the detection function is bass-weighted (`0.7·bass_flux + 0.3·flux`, `Onset::strength`), crossing `max(mean + 2.2σ, 2.5×mean)` of the last ~4s only **arms**, and the switch **commits** when the transient turns over with the low end held up 1.18× for 3 frames (a riser is a narrow sweep; the thing it leads into brings the kick back — and a kick rings for several frames where noise jitter lasts one). Every threshold needs its ratio floor as well as its sigma term: in steady passages the spread collapses toward zero and a sigma-only test fires on nothing at all, which then eats the next real drop via the hold. 9s hold, 45s backstop so ambient tracks still move. The next scene is picked at **random**, excluding the current one and the one before it — a fixed rotation is predictable after one pass, and an unconstrained pick repeats or ping-pongs. Changes cross-fade over 220ms (incoming rises fast so the cut lands on the beat). While a scene runs the overlay's big cover + info column stands down and a **floating mini player** (cover thumb, title/artist, transport, seek bar, and the scene picker: `Off` and `Auto` as buttons, every scene behind one `More` popover — a button per scene crowded the card and buried the two entries that are not scenes) floats over the scene instead — so the visualizer gets the whole window and its controls live in it. Queue/Lyrics panels and the optional volume slider belong to the normal layout and are not in the mini player. The mini player's slider button opens the **tuning card** (`VizKnob` in `fullscreen_player.rs`): sensitivity (band gain), smoothing (attack/release), reaction depth (`power`, how far the audio deforms each scene), motion speed, and the two Auto-only knobs (switch sensitivity, scene hold). It floats over the running scene on purpose — every one of these is judged by eye — and writes `Settings::visualizer_tuning`, which `tick` re-reads each frame, so a drag retunes live. Defaults reproduce the untuned look exactly. Terrain rows widen with depth (`terrain_row_half`) so no row ever ends inside the window; a constant-width grid shrinks as 1/z and reads as a floating carpet. `Visualizer::tick` runs one FFT per frame; the fullscreen player calls `window.request_animation_frame()` while a scene is on, and nothing at all when it is off.
  - `ui/mod.rs` — shared helpers, theming included. `accent_from_cover_bytes` (the Adaptive theme's cover-derived accent) returns `None` **only** when the image fails to decode: it tries a vivid pass, then a relaxed one with no lightness penalty, then a neutral accent built from the cover's mean lightness. Very dark and very bright covers failed the vivid pass outright, and the accent then silently stayed on the *previous* album's colour. `RootView::maybe_update_adaptive_accent` matches: it resolves local tracks' art straight off disk (no client, no server cover id) and clears its remembered art key when extraction fails, so the next player notify retries instead of pinning the old colour.
  - `config.rs` — settings TOML via `directories::ProjectDirs`; password in OS keyring (`keyring` crate), plaintext-in-settings fallback only when keyring fails. Also owns the cache dirs (artwork, waveform peaks), persisted UI prefs (`default_page`, `album_sort`, selected `library_ids` — legacy single `library_id` is migrated on load), and `local_music_dirs: Vec<PathBuf>` for local file scanning.

### Async pattern (used everywhere in the app crate)

```rust
cx.spawn(async move |this, cx| {
    let data = runtime::spawn_io(async move { client.some_call().await.map_err(anyhow::Error::from) }).await;
    let _ = this.update(cx, |view, cx| { /* apply */ cx.notify(); });
}).detach();
```

Never block gpui's executor with IO; never share locks with UI state — entities are mutated only via `update`.

## Pinning & toolchain notes

- **gpui `0.2.2` + gpui-component `0.5.1` are a matched crates.io pair** (gpui-component depends on `gpui ^0.2.2`). Do NOT bump one without the other; do NOT switch to git deps casually — gpui-component `main` tracks Zed `main` and churns. gpui types stay confined to `crates/app`.
- gpui is built with the `runtime_shaders` feature: required on machines with Command Line Tools only (no `xcrun metal`). Don't remove it.
- `[profile.dev.package.{gpui,gpui-macros,gpui-component}] opt-level = 2` — only the heavy gpui deps, not all workspace crates.
- rodio is built with `symphonia-all`. Its defaults only cover flac/mp3/aac-in-mp4/vorbis/wav, so raw streams of ALAC (m4a), aiff, mkv, caf or adpcm fail with "The format of the data has not been recognized" — rodio reports a missing *codec* as an unrecognized *format*. Covered by `plays_alac_m4a_stream` in `crates/playback/tests/engine_test.rs`.
- Edition 2024 across the workspace; let-chains are used (`if let … && …`).
- `souvlaki` (media keys / MPRIS) needs `dbus` on Linux; init is best-effort and `MediaKeys` degrades to a no-op if the backend is unavailable, so it never blocks startup.

## Testing conventions

- `subsonic`: wiremock integration tests in `tests/client_test.rs` — token/auth param assertions, envelope parsing from realistic Navidrome JSON, error-code mapping. Add a wiremock test for every new endpoint.
- `playback`: `tests/engine_test.rs` streams a generated in-memory WAV from a wiremock server through the full engine and asserts the event sequence; also tests local file playback via `plays_local_wav_to_completion` (temp WAV file) and `local_file_missing_errors` (non-existent path). Self-skips when no audio device exists (CI).
- Manual smoke: demo.navidrome.org (user `demo`/`demo`) or `docker run deluan/navidrome`. Navidrome quirk: folder browsing is simulated — only use ID3 endpoints (`getArtists`/`getAlbum*`), never `getIndexes`/`getMusicDirectory`.
- Scrobbling is server-side: client only calls `/rest/scrobble` (`submission=false` on start, `true` at ≥50%/4min); Navidrome forwards to ListenBrainz/Last.fm itself.

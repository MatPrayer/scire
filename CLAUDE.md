# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Scirè** — cross-platform (macOS + Linux) desktop music client for [Navidrome](https://www.navidrome.org/) servers and local music files, built with GPUI (Zed's UI framework) + [gpui-component](https://github.com/longbridge/gpui-component). Speaks Subsonic API v1.16.1 + OpenSubsonic; identifies as `scire` in the Subsonic `c` param. Local music support: engine reads local files via `SourceReader::Local(File)`, responsive virtualized album grid with viewport-scoped, size-bucketed cover textures (DB refreshed via `scan_version`; `local_music.rs` keys its in-flight cover jobs by album id and prunes them to the visible window, since dropping a `gpui::Task` cancels it — capping a flat list instead cancelled by *age*, which during a fast scroll is the cards now on screen, left blank with nothing to re-request them), album detail view with track listing (`LocalAlbumDetailView`), incremental mtime-based scanner, periodic background scan (5 min). See `README.md` for the user-facing feature list and Linux build deps.

## Versioning

`[workspace.package] version` in `Cargo.toml` is the single source of truth. Two things mirror it and must move in the same commit: the README badge (`badge/version-<x.y.z>-6f7ce8`) and `Cargo.lock`, where **all four workspace members** (`scire`, `subsonic`, `playback`, `dmg`) carry the inherited version — any `cargo check` rewrites them, stage the result. The macOS bundle reads the version out of `Cargo.toml` at package time, so `packaging/macos/bundle.sh` after a bump needs a fresh `cargo build --release` first or it wraps the old binary under the new number.

Versions follow [Semantic Versioning 2.0.0](https://semver.org/). Given a version `MAJOR.MINOR.PATCH`, increment:

- **MAJOR** for incompatible public API changes.
- **MINOR** for backward-compatible functionality.
- **PATCH** for backward-compatible bug fixes.

Major version `0` denotes initial development, where the public API is not stable. Pre-release and build metadata use SemVer syntax and precedence rules. The bump ships **in the commit that makes the change** — never a separate "bump version" commit. Refactors, tests, docs and comment-only changes do not require a bump.

If the change is already pushed when the bump is noticed, it goes in its own follow-up commit (`chore: bump version to x.y.z`) rather than an amend — rewriting published history costs more than a tidy log is worth.

## Architecture

Cargo workspace, three crates with a strict dependency direction — UI → services → protocol:

- **`crates/subsonic`** — pure async Subsonic/OpenSubsonic API client. reqwest + serde only; NO gpui, NO audio. Every request carries fresh token auth (`t = md5(password+salt)`, new salt per request, built in `auth.rs`). `client.rs` owns the request core + `subsonic-response` envelope unwrapping + typed error codes (40 = bad credentials, 50 = not authorized). Its one shared `reqwest::Client` is built with a 300s `pool_idle_timeout` (reqwest defaults to 90s): against a remote server the TLS handshake is ~90ms of a ~190ms cold request versus ~80ms on a pooled one, and navigation minutes apart otherwise pays it every time. It also carries a 10s `connect_timeout` and a 30s `read_timeout`, neither of which reqwest sets by default: a host that drops packets is otherwise left to the OS, which retries the SYN for over two minutes, and with only two IO workers every request behind it waits — "the whole app froze" was a listing that was never going to arrive and could not fail. The read timeout is per-gap rather than total because `getArtists` returns a whole library in one body and a total cap would abort a large one on a slow link. Failures are wrapped by `http_error`, which calls reqwest's `without_url()` **before** the error leaves the crate: every request URL carries `u`, `t` (the auth token) and `s` (the salt), and `reqwest::Error`'s `Display` prints the URL it failed on — so a dropped connection used to paint the account's token across whatever view rendered the error. `Error::user_message()` is the UI's wording for each case (no URL, no library jargon, an action where there is one) and `Error::is_transient()` decides whether a Retry is worth offering — a timeout, a refused connection, a 5xx or a 429, but never wrong credentials, a bad URL or a 404, which fail identically forever. The crate is HTTP/1.1 only (`default-features = false` drops the `http2` feature), so concurrent requests each hold their own connection. Endpoint methods live in `endpoints/{system,browsing,lists,media,playlists,annotation,radio}.rs`. `system.rs` also carries `start_scan()`/`get_scan_status()` → `ScanStatus { scanning, count }`, behind Settings → Library → *Scan server library*; Navidrome restricts `startScan` to admins, so a failure means "the server won't rescan for us" and is reported, not fatal. All catalog methods accept `music_folder_id: Option<&LibraryId>` (multi-library, wired to UI in M3). `media.rs` carries **both** lyrics endpoints, and the by-id one is the one that answers: Navidrome collects lyrics at scan time out of the file's tags *and* out of a sidecar `.lrc`, and publishes them only under the song's own id (`getLyricsBySongId` → `Vec<StructuredLyrics>`, the OpenSubsonic `songLyrics` extension, one document per language plus a synced and an unsynced copy of the same words, `line[].start` in ms). Classic `get_lyrics(artist, title)` searches the library by tag text instead and misses everything whose tags don't match what was sent, which is most of a library — it is kept only as the fallback for servers without the extension, which answer the by-id call with error 70. An empty `"lyricsList":{}` (Navidrome's answer for a song it has nothing for) parses as an empty list, not a decode error, so both levels of the wrapper default. `stream_url()`/`cover_art_url()` build authenticated URLs without issuing requests — playback/artwork layers fetch them. `Song` struct has an optional `local_path: Option<String>` field (serde-skipped when `None`) for local file tracks.
- **`crates/playback`** — audio engine behind a command/event facade (`Player` handle ↔ `Event` stream via tokio mpsc). Internals: rodio 0.22 (`DeviceSinkBuilder`/`MixerDeviceSink`/`Player` — note rodio renamed Sink→Player in 0.22) + stream-download (HTTP → blocking `Read+Seek` with ranged re-requests for seek). `TrackSource` supports both HTTP streaming and local files via `SourceReader` enum (`Http(StreamDownload)` / `Local(File)`). Both shared HTTP clients carry a 10s `connect_timeout` and a 30s `read_timeout` — reqwest sets neither, and `Command::Play` awaits the open **inline on the control loop**, so a server that drops packets left the engine answering no command at all while the OS retried the SYN. `PlaybackError::from_http` puts every HTTP-side message through `scrub_urls`, which cuts the query off any URL it quotes: a Subsonic stream URL carries the auth token and the salt there, and the message ends up on the player bar. When `TrackSource.path` is `Some`, `source::open_local()` opens the file directly — no network round-trip. **`TrackSource.live` marks internet radio**, and only live sources are opened with the ICY client (`Icy-MetaData: 1`): that header asks the server to interleave now-playing titles, and a server that honours it on a *library* file answers without a `Content-Length`. No length means `with_seekable(false)`, and an unseekable m4a whose `moov` index sits after the audio (anything not written with faststart) cannot be read at all — so the header used to break a subset of ALAC/AAC files and nothing else. `source::open`/`open_local` return an `Opened` carrying a `Hint` (response MIME type, or the file extension) which is passed to the decoder as `with_mime_type`/`with_hint` (symphonia 0.5.5 ignores it — it takes the argument as `_hint` and identifies formats from marker bytes — so the hint's present value is the failure message below, not the probe). `engine::decoder_failure` translates the result: rodio collapses **every** symphonia `Unsupported` — missing `moov`, more than one `stsd` sample entry, an unknown ALAC magic cookie — into one `UnrecognizedFormat` reading "the format of the data has not been recognized", so for an MP4/M4A hint the message is rewritten to name the actual cause (no length vs. a server ignoring ranged requests) and the original is logged. A prefetch that fails no longer dies in a log line: `Event::PrefetchFailed { id, error }` reports it while the current track still plays. The facade hides rodio completely so the engine can be swapped. Must be constructed inside a tokio runtime context. **Gapless**: one `rodio::Player` lives across tracks; `PrefetchNext` prepares the next decoder, and the engine appends it into that player's queue only once the current track is within `COMMIT_LEAD` (3s) of its end — rodio then hands over sample-continuously. An appended track cannot be withdrawn (rodio's queue has no removal), which is why the commit is deliberately late; `TrackEnded { auto_advanced, started }` reports the id that actually started so the consumer can resync if the queue changed inside that window. The hand-over instant comes from the `EndSignal` source wrapper (`source.rs`), not from polling `Player::empty()`. **Seeking runs off the control loop** (`spawn_seek`, and `sink` is an `Arc<rodio::Player>` so the blocking task can keep the player alive): `rodio::Player::try_seek` blocks until the audio thread has moved the decoder, and over HTTP that means symphonia binary-searching the container with a ranged re-request for every probe that lands outside what stream-download already has on disk — measured at 5s idle and 30s (six requests) against a remote Navidrome while the app was still starting up. Run inline it held the whole loop: no pause, no next, no position ticks, and with only two IO workers in the app it was competing with the very requests it was waiting on, which is what "press play after reopening the app and everything freezes" was. The worst case is a *restored playback position*, applied the instant the track opens, when nothing is downloaded yet. While a seek is in flight the tick reports the **destination** rather than `get_pos()` (which still reads the position being left — the app was writing that back over the resume file and painting 0:00) and skips the route watch entirely, since tearing the output down under a blocking seek leaves it waiting on an audio thread that no longer exists. A seek still running at the next tick (500ms) sends `Event::Buffering`, and its completion sends `Playing`/`Paused` to clear it — a seek quick enough to finish inside one tick never announces anything, so dragging the seek bar does not flicker the transport. A result arriving for a sink that has since been replaced is dropped on the generation counter (`cancel_seek`). The device-switch and route-change paths seek the same way: they reopen the track at zero and then move it, which is the same long seek. **Output routing**: the `MixerDeviceSink` outlives every track played through it and is only ever opened when there is none, so the engine watches the route on its tick — `route_lost` compares the device the sink was opened on (`open_device`) against the OS default (or, with a device chosen in the picker, against its continued presence). The watch runs while **idle** too (`IDLE_ROUTE_CHECK_TICKS`, ~8s, against ~2s while playing): earbuds connected between tracks are otherwise never noticed, since nothing drops the stale output, and only restarting the app fixes it. `Command::Play` drops a stale output before opening the new track rather than letting the tick tear one down mid-playback, and `Resume` forces the next tick to check. What a change *means* is `route_action` (pure, unit-tested): a device pulled out from under playback is `HoldForDevice` — pause, and resume only when that same device returns (`lost_device`) — while a route that merely moved to a device that just appeared is `Follow`, and keeps playing on it. `route_grace` marks a Play/Resume since the last check, so an explicit request for audio outranks waiting for a device that went away while paused. `route_lost` itself is one comparison — "where would audio go if we opened now" (`resolved_device_name`) against where this sink *was* opened — which is also why `resolved_device_name` reports the **fallback** when a chosen device is missing rather than the chosen name: the honest answer is what lets the watch notice the device coming back and go claim it. **On Linux the whole device layer is `pactl`, not cpal** (`crates/playback/src/pulse.rs`): cpal's ALSA backend enumerates ALSA *hints* — resampler plugins, sound servers, capture-only devices — and cannot see PipeWire sinks at all, so a Bluetooth headset never appeared in the picker. `output_devices()`, `device_present` and the default-route name all come from `pactl list sinks` descriptions there (cpal stays as the fallback for a box without `pactl`, and is still the whole story on macOS). cpal cannot *open* a PipeWire sink either, so `open_output` opens the default stream and `retarget_stream` moves it with `pactl move-sink-input`, identifying our own sink-input by `node.name = "alsa_playback.<exe>"` (pipewire-alsa publishes no process id). Two traps, both hit in practice: opening a device briefly registers a node that is **not** the one that ends up playing, so a move must be read back rather than trusted — and a stream mid-move reports sink id `u32::MAX`, which means "ask again", not "somewhere else". A desktop that routes streams itself (EasyEffects sits in front of every output) will accept the move and undo it within a few hundred ms; that is `MoveResult::Grabbed`, and the engine logs it and stops rather than fighting a loop it cannot win. Also exports `spectrum` — the real-time visualizer feed: a `Tap<S>` source wrapper (same shape as `EndSignal`, inserted in `engine::append` so every track flows through it) mirrors output samples, downmixed to mono, into a lock-free `SpectrumTap` ring (`AtomicU32` bit patterns behind a monotonic write counter — the audio thread never locks); `spectrum::analyze` windows 4096 samples, runs a hand-rolled radix-2 FFT (no FFT dependency) and reduces it to log-spaced bands. `Player::spectrum_tap()` hands the ring to consumers; an unchanged write counter means no audio flowed, so consumers decay instead of freezing. Also exports `waveform::peaks_from_bytes` — offline decode of a full track into normalized RMS loudness buckets (gamma-expanded so compressed masters stay readable); pure CPU, call from a blocking context.
- **`crates/app`** — the gpui binary (package name `scire`). Layers:
  - `services/runtime.rs` — the gpui↔tokio bridge: global 2-worker tokio runtime; `spawn_io(fut)` spawns there and returns a runtime-agnostic future awaited from gpui tasks; `enter(f)` for constructing tokio-dependent types (the playback engine). **Only two workers, so blocking work must go to `spawn_blocking_io(closure)`** (the local scanner, whole-track decodes) — a closure that never yields pins a worker for its whole run and every HTTP request behind it waits, which is how a long local scan used to stall the album grid's first page. Note also that gpui tasks (`cx.spawn`) have no tokio reactor in scope: `tokio::time::sleep` panics there, use `cx.background_executor().timer()`. `services/artwork.rs` — cover-art fetch + disk cache. **Navidrome quirk**: every song gets its own `coverArt` id (`mf-<songId>_<hash>`) even within one album, so caching or change-detecting on it re-downloads identical album art for every track. `song_cover(&Song)` returns `(cover id to request, album-scoped cache key)` and `fetch_as`/`cached` take that key — use them for anything rendering a *song's* cover (player bar, fullscreen, adaptive accent, recent, search). Album/artist covers already carry stable ids and use plain `fetch`. **Art is center-cropped square on the way into the cache** (`square_crop`, also used by the local scanner and the remote artist-photo download): gpui's default `ObjectFit::Contain` letterboxes non-square art inside the square tiles every view draws, and `ObjectFit::Cover` is not the fix — it paints the image *outside* the element's bounds, gpui's only clip is a rectangular content mask, and the corner radii are applied to that oversized quad, so the rounding lands off-tile and is cut away. A square file needs no fit at all. Dimensions come from the header, so the common case (art already square) never pays for a decode; a format the `image` crate is not built with (only jpeg + png) fails the read and is stored untouched. Every write into either cache goes through `write_atomic`, whose temp name carries a per-call counter as well as the pid: two jobs for the *same* cover are ordinary (a grid drawing an album twice, a prefetch and a view asking at once), and one shared `key-256.part` lets the second truncate what the first is about to rename — a half-written image published into a cache keyed by content, which is never re-fetched. A rename that loses to a duplicate writing identical bytes is the race resolving correctly and counts as success. Both caches are keyed by cover id and size rather than content, so art cached before this is squared **in place** by `squarify_cached_art` (startup, blocking pool, one marker file per cache dir — `SQUARED_MARKER` is public so the local cache's own prune knows not to collect it, a marker nothing references otherwise reading as an orphan and its deletion re-running the whole squaring pass next launch) — a key bump would re-download the server's whole library and would blank the local covers outright, since the scanner re-extracts art only for files whose mtime moved. `bucket` is **public** because a view has to be able to tell a size change that matters from one that does not — the four `CoverSize` widths land on three rungs (Medium and Large share 512), and the album grid's "the setting moved, refetch" guard compares rungs rather than raw widths. `services/art_precache.rs` — the optional bulk warm-up behind `Settings::precache_art` (Settings → Library → *Preload all cover art*): walks the synced catalog's album and artist rows, skips every cover already cached at the grid's rung, and fetches the rest `PRECACHE_CONCURRENCY` (2) at a time — deliberately well under `artwork`'s own semaphore, which it shares with the grids, so a precache never puts the cover the user is looking at behind a few thousand they are not. Local rows are skipped: their art is already on disk from the scanner. `RootView::maybe_precache_art` starts it after each sync (startup and the sidebar refresh, one pass at a time via `precaching`), where it sees the albums that sync just wrote; the Settings switch starts one immediately and is the only path that draws a progress line. A pass over a warm cache is a walk of two tables and no requests, which is what makes leaving it on cheap. `services/waveform.rs` — seek-bar peaks: downloads a low-bitrate transcode (amplitude envelope survives lossy compression), reduces it via `playback::waveform` to 480 buckets, caches JSON on disk keyed by song id (`.v3` cache version suffix — bump it when the bucket format changes). `PlayerState::prewarm_next_waveform` (fired from `refresh_prefetch`, gated on the `waveform_seekbar` setting mirrored into `waveform_enabled`) computes the *next* track's peaks during the current one, so the bar draws instantly on the hand-over; `fetch_peaks` holds a per-song-id lock so a prewarm and the view asking for the same peaks never both download and decode. `services/library_db.rs` — SQLite music library database (`~/.cache/scire/music.db`) with `tracks`, `albums`, `artists`, `track_artists`, `album_artists`, `config` tables and simple integer migration (`_schema_version`, currently 8 — v8 adds local technical/file/ReplayGain metadata and marks local scan fingerprints stale so the next scan backfills unchanged files without deleting playlists; v4 adds the source/`album_id` indexes; without `idx_tracks_album` the per-album track count in `album_fingerprints` is a full scan of the track table *per album*, ~2.3s over 1126 albums. v5 indexes `tracks.artist_id` and **deletes every synced track row**: the sync used to write the album's artist id onto all of its tracks, so a featured artist was indistinguishable from the credited one, and an incremental sync would never re-fetch rows whose count and duration had not moved — an empty track table is the "tracks never landed" case `needs_track_fetch` already treats as stale, so the next ordinary sync refills them. v6 adds `track_artists` and drops the synced tracks again for the same reason: `tracks.artist_id` is a *single* id and Subsonic's `artistId` is the **primary** credit, so a remix released as "irossa • Amore Audio" carries irossa's id and nothing else and the guest is unfindable however the track rows are queried — only OpenSubsonic's per-song `artists` array spells the collaboration out, and `set_track_artists` records one row per credit. Both delete paths (`delete_track`, `delete_tracks_for_album`) clear it alongside the tracks; SQLite has no cascade here. v7 does the same one level up with `album_artists`: `albums.artist_id` is one id and `albums.artist` is the server's *display* string, so an album by two artists comes back as `artist: "A • B"` with the `artistId` of A alone — "credited to someone else" cannot be asked of the album row, and B's own record was listed as an appearance on it. No wipe: `getAlbumList2` carries the credits and the sync rewrites every album row it lists on every pass, so they fill on the next ordinary sync with no extra requests). `album_libraries` and `appears_on` answer the two questions `getArtist` cannot: which music folder an album was synced from, and which albums an artist plays on without being credited with them — a track they are *credited on* (`track_artists`, not `tracks.artist_id`) on an album they are *not* credited on (`album_artists`, not `albums.artist_id`); both `artist_id` columns hold the server's primary credit only, and neither names the other participant in a collaboration. Every step runs through `migration_step`, which applies the batch **and** the `_schema_version` row it earns in one transaction: SQLite makes DDL transactional, and autocommitted a batch that dies partway (v8 is twelve `ALTER`s) leaves the columns that did land without the version saying so — the next launch re-runs the batch from the top, hits `duplicate column name`, and the database never opens again, playlists included. Thread-safe via `Mutex<Connection>`. `album_by_id` takes a source as well as the id, but `albums.id` is the primary key on its own, so that is a guard against a local album standing in for a server one, not a namespace. **Write in batches**: SQLite autocommits per statement, so `upsert_catalog` wraps the album/artist rewrite in one transaction — a thousand single upserts was seconds of an otherwise sub-second sync. `LibraryDb::library_stats(source, library_ids)` backs the catalog headers' totals; it counts from the **album** rows' `song_count`/`duration` rather than the track table, because an incremental sync only pulls tracks for albums that moved and counting those would report a fraction of the library. `services/local_library.rs` — synchronous directory scanner using `lofty` for tag and audio-property reading; walks `local_music_dirs`, extracts folders (`folder.jpg` / embedded art), technical/file/ReplayGain metadata, and upserts tracks/albums/artists into `LibraryDb`. Local album Added dates use the earliest filesystem creation time and stay absent where the filesystem exposes none. Its scoped cache rebuild keeps current covers live, invalidates local mtime fingerprints, rescans with content-hashed folder art, then prunes only unreferenced generated files from `local_art/`; failed scans keep old art and music files are never touched. Progress atomics (`AtomicU8` status, `AtomicUsize` count), plus a process-global `SCAN_IN_FLIGHT` — the 5-minute background rescan and the manual refresh each build their own `LocalScanner`, so a per-instance flag doesn't see the other one and the two walks fought over the SQLite write lock with half-filled `seen` sets; a second `scan` while one runs returns `Ok(())` without scanning, so its tests must serialise on the module's `SCAN_TESTS` mutex or they see IDLE. `services/navidrome_sync.rs` — reconciles the Navidrome catalog into `LibraryDb` with source=`navidrome`. Three phases: **list** every album (paginated `getAlbumList2`), **reconcile** against the cache, then **fetch tracks** for the albums that need it, `ALBUM_FETCH_CONCURRENCY` (6) `getAlbum` calls at a time via a `JoinSet`.

`SyncMode::Incremental` (everything except the Settings rebuild) is what makes this cheap: the listing already carries each album's `songCount`/`duration`, so `needs_track_fetch` compares them against `LibraryDb::album_fingerprints` and issues a `getAlbum` **only** for albums that are new or have moved. A settled library costs the three listing requests and a local compare; before this every sync was one `getAlbum` per album whether or not anything had changed (~1100 albums took minutes serially, ~17s at concurrency 6, ~1s incrementally). `track_rows` in the fingerprint is `COUNT(*)` rather than the stored `song_count` because a sync interrupted between phases leaves album rows whose tracks never landed, and those must not look complete. Duration is compared with a 1s tolerance — servers round it and it round-trips through an f64 column, and an exact compare re-fetched albums that hadn't changed. The album *row* is always rewritten even when tracks are skipped: `play_count`/`starred` are the Frequent/Starred tabs' sort keys and move without the track list changing. Albums the listing no longer contains are deleted with their tracks, then `prune_orphan_artists` sweeps up. `fetch_album_tracks` clears the album's tracks before re-inserting, since upserts alone would strand rows for songs deleted from the album (the old full wipe covered that implicitly), and writes each song's **own** `artistId` rather than the album's (songs without one still fall back to the album artist). That column is only the primary credit, so `song_credits` also writes the song's whole OpenSubsonic `artists` array into `track_artists` — that is what the artist page's "Appears on" section reads, and neither the album artist nor `artistId` names the guest on a collaboration. The listing phase does the same for albums: `album_credits` fills `album_artists` and the **artist rows**, each credit under its own name — `album.artist` is a display string joining every name, so taking the `artist`/`artistId` pair at face value filed the first artist under "A • B" and never recorded the second at all. `SyncMode::Full` wipes first and so finds no fingerprints, making every album stale — the escape hatch for the one thing incremental cannot see, an album re-tagged without its track count or duration moving.

Walks one music folder at a time (`getMusicFolders` first) so every row records the `library_id` it came from — that provenance is what lets the grids seed their cache for a library *subset*. Pagination stops on a short page, and on a page whose head id repeats the previous page's *within the same folder* — a server ignoring `offset` otherwise loops forever, and comparing against the global `seen` set instead would truncate a second library that shares albums with the first. Publishes `SyncProgress` (`total`/`done` atomics) for the UI. Started once per session from `root.rs` behind its own `sync_started` flag (separate from the local scan's — one shared flag meant it never ran for anyone with local dirs configured) and delayed 30s so it doesn't compete with the album grid's own first page. Also exports `run_server_scan` (`startScan` + poll `getScanStatus`), which runs inside the tokio runtime and so can use `tokio::time` directly, unlike the gpui tasks calling it.

**Two different operations, deliberately split.** The sidebar's **Refresh library** row (`RootView::refresh_library`) is the fast, frequent one: local scan (blocking pool) then an incremental reconcile, in sequence because two IO workers can't carry both. It does *not* ask the server to rescan its disk — pairing them made every refresh cost a full server walk, which is minutes. The server rescan lives in **Settings → Library** alongside **Rebuild local cache** (local art reset + forced local scan, followed by a `SyncMode::Full` sync when connected); both are slow, occasional jobs, both report a status line rather than a bar since neither has a meaningful total, and `startScan` is admin-only on Navidrome so its error 50 is surfaced to the user rather than swallowed. `run_server_scan`'s grace period covers Navidrome reporting `scanning: false` for a moment after accepting the request — an idle reading only counts once the scan has been seen running, or after the grace elapses.

Progress reaches the sidebar as `RefreshStage` (a `root.rs` enum, unit-tested). Workers publish into atomics; `ui::poll_until_done` awaits the job on `cx.background_spawn` and samples them on a gpui timer (shared by the sidebar refresh and both Settings jobs). Only the import stage has a real denominator, so it alone draws a filled bar — the others report a rising count against no total and get a bare track rather than a bar creeping toward a made-up finish. A refresh that finds nothing new never leaves the `Comparing` wording, which is why `Import(_, 0)` reads the same. On completion the catalog views are dropped and the current page redrawn, but only if it is still one of the listings (a detail view opened meanwhile must not be swapped out from under the user). A step that *fails* is no longer only logged: `drive_progress` returns the failure and `RootView::refresh_error` puts it under the refresh row (in the tooltip when the rail is folded, which is the only room there is). A refresh against an unreachable server otherwise stopped the spinner and said nothing, which is indistinguishable from one that found no new music.
  - `state/` — gpui Entities and pure logic: `session.rs` (settings, SubsonicClient, connect flow, music-folder list + library selection), `player.rs` (owns the queue/position/volume, consumes playback events — the single audio↔UI touchpoint — and drives scrobbling, prefetch, media keys, radio), `queue.rs` (pure queue model: shuffle/repeat/reorder, unit-tested), `scrobble.rs` (pure threshold state machine, unit-tested), `playlists.rs` + `radio.rs` (shared CRUD state), `media.rs` (souvlaki OS media controls, best-effort). `player.rs` distinguishes library playback (queue + Subsonic stream URLs) from live radio (`play_radio`, external URL, seek disabled). `Event::Failed` **skips to the next track** instead of stopping the queue — one unplayable file must not end the session — but only while `failed_streak < MAX_FAILED_STREAK` (5), since a run of failures is the server or the network being gone and walking the whole queue into it is one dead request per track. The streak is cleared by `Event::Playing` and by `start_current`, which is why the failure path re-applies both it and `last_error` after calling it; the error text stays on the player bar until the track after the skipped one starts. `Event::PrefetchFailed` puts "Next track unavailable: …" there while the current track keeps playing. **Before the skip, a remote track is asked for once more transcoded** (`retryable_transcode` → `transcode_retry`, one song id so it cannot repeat, and the streak is re-applied so a dead server is still counted): symphonia decodes FLAC up to 24 bits per sample and reports a **32-bit** FLAC — what `flac -b 32` and several CD rippers now write — as `IoError("end of stream")` from inside the first frame, naming nothing. `unplayable_as_stored`/`stream_opts_for` (pure, unit-tested) catch the case ahead of the failure where the server publishes a bit depth (OpenSubsonic `bitDepth`), so nothing is heard at all; the retry covers the servers that don't. The forced options are `format=mp3` (the one transcoding profile every server ships configured) at 320kbps, and a format the *user* has set wins over them — they asked for a transcode already — except `raw`, which is the absence of one spelled out. A local file has no server to re-ask, so a 32-bit FLAC on disk still fails. **ReplayGain is applied by scaling the engine volume**: `replaygain_linear` (pure, unit-tested) turns a song's OpenSubsonic `replayGain` block into a linear multiplier (`10^((gain+baseGain)/20)`, album gain/peak in Album mode falling back to the track's, `fallbackGain` for an untagged file), holds it under `1/peak` so a boost cannot clip, and `effective_volume` multiplies it by the user's own volume. That product routinely exceeds 1.0 — a quiet master's gain is *positive*, and rodio's volume is a plain linear sample multiplier — so the ceiling shared by both sides is `playback::MAX_VOLUME` (4.0) rather than 1.0: the engine clamped `SetVolume` at unity and silently dropped every boost while attenuation kept working, i.e. normalization only ever made things quieter. `Auto` resolves to Album when the queue is one album and Track otherwise, so the gain is recomputed on queue edits as well as on each track. A **local** track carries no tags at all — the scanner reads none and `Track::into_song` leaves `replay_gain` `None` — so a local library is unnormalized whatever the mode says. The queue itself is always persisted (`queue.json`); the **position** inside the current track is only kept when `Settings::resume_playback` is on, in its own `resume.json` — separate because it is rewritten as playback runs (once per whole second, from `Event::Position`, plus a forced write on pause) rather than only on queue edits. Saving as it goes rather than at quit is deliberate: a crash or SIGKILL never runs a shutdown hook. On startup the saved position is only taken if it names the same song the restored queue is sitting on, and it is applied as a **pending seek** — the engine can't seek a source it hasn't opened, so the seek waits for that track's first `Playing` event, and is dropped if the user skips to another track first.

Two things decide whether a placeholder is an improvement, and both were got wrong first. **The space is reserved from the first frame; only the grey waits `PLACEHOLDER_DELAY` (220ms)** — `loading_album`/`loading_info` (is a request in flight) and `show_album`/`show_info` (`placeholding`, over `album_since`/`info_since`) are deliberately separate, and `skeleton_pulse` takes the second as `show`: an unshown placeholder keeps its element and its sample text, and so its exact size, losing only the fill and the animation. Gating the *space* on the delay, which is what it did first, does not remove the shift — it postpones it to whenever the gate opens, and a warm server lands inside 220ms so the page went back to visibly assembling itself. Gating the *paint* is what fixes the flash it was reaching for: below the delay the words drop into a hole of exactly their own size and nothing moves, past it the request is slow enough that saying so is the point. The deadline is not an event and a clock running out dirties nothing, so `wake_at_placeholder_delay` schedules the repaint that lets the grey appear at all. And each placeholder is **shaped by a sample string laid out in the type styles of the field it replaces** (`skeleton_text`, `skeleton_chip`, `skeleton_line`, all over `skeleton_pulse`), not sized in px: the fields are text, so the only height guaranteed to match the line that lands is the one the text engine produces for the same styles, and hand-picked px were a few off in every place they were used — the page still stepped, which is the whole thing they exist to stop. The sample is painted `transparent_black` and is there for its metrics alone; the skeleton track rows carry the real row's padding, columns and an `invisible()` copy of its hover buttons, since those are what set its height (measured: 34px either way). `skeleton_line` takes an explicit width for one line of prose; `skeleton_block` takes a *sample paragraph* (`notes_sample`, `NOTES_PREVIEW_CHARS` of it) and fills its column, since how many lines the About card's notes wrap to is a property of the window and a fixed number of bars stood in for six lines on a narrow one. **What has to match is the count, not only the height of each piece.** Both remaining steps were of that kind and both showed up only in the *stacked* layout, where the header sits on top of the track list and anything it gains pushes the whole page down — in the side-panel layout the two are separate columns and neither was ever seen to move. The chip row reserved four placeholders where `quality_chips` yields **five** (format, bitrate, rate/depth, channels, size — genre and "Added" are in the cache already, so a seeded page draws them itself), and the row wraps, so the fifth arriving took the header a line taller. **And some heights cannot be placeheld at all, which is an ordering problem rather than a sizing one.** The About card's prose is an unknown number of words wrapped in a column whose width is the window's, its More/Less button exists only when the notes run past `NOTES_PREVIEW_CHARS`, its links exist only when the server has them, and a server with no metadata agent answers with nothing and the card never appears — no sample can stand in for a card that may be six lines, two lines or absent. So in the **stacked** layout it is drawn *below* the track list, where what it gains grows into empty page and there is nothing above it to push, and no placeholder is built for it at all; the side-panel layout keeps it in the panel, where it can only move itself, and there the placeholder (prose block, an `invisible()` More button, the links row) is still worth holding. The ReplayGain line is the same shape of problem one size down and takes the other way out: the tags live on the songs, so the line is `getAlbum`-only, and one that *disappears* when the response says "no gain tags" steps the page exactly as much as one that appears — its slot is therefore reserved unconditionally, grey past the delay and an empty line of the same metrics once loaded, which costs an album without gain tags one faint blank row and costs every album the step. The skeleton track list is `expected_tracks` long — `cached_song_count`, the album row's own `song_count`, which the cache has even for an album whose *tracks* never landed and so whose rows `cached_album` refuses to seed — falling back to `TRACK_SKELETONS` (8) only when the cache has never heard of the album at all. gpui-component's `Skeleton` is not used: it is a childless `div`, so a placeholder built on it can only be given a size in px. `album_pending`/`album_loaded` and `info_pending`/`info_loaded` gate them: *pending* alone is not enough, since `load` re-runs whenever playback enters or leaves the album and swapping chips a user is reading for placeholders is worse than the shift they prevent, and *loaded* alone is not enough either — a page with no client has nothing in flight and must show what it has rather than wait on nothing. **`Settings::album_layout`** (`config::AlbumPageLayout`, Settings → Album pages → *Layout*) turns both album pages — server and local — inside out: track list down the left, cover and details in a tall panel on the right, each column scrolling on its own (a long album scrolled under a panel that stays put is the point). The content width the panel is sized from is `scroll.bounds() + panel_w`, not the bounds alone — `scroll` tracks the *track list*, which in this layout is the content area minus the very panel being sized, so measuring it alone would have the panel shrink itself every frame; they are gapless siblings, so the sum is the content width in either layout. Nothing is measured on the view's **first** frame, so the panel cannot be sized and the page can only be laid out stacked — and a measurement landing dirties nothing, so that stacked frame stayed up until the next repaint, which for a freshly opened album is `load` returning: the wrong layout visible for a whole network round trip. Opacity, not `hidden()`, since `display: none` would skip the very layout pass the frame exists for; and it goes on the layout's own root rather than a wrapper, so the stacked page is not restructured to spare one frame of the other. **Window resizing.** Anything whose shape depends on the window width derives it from `window.viewport_size()`, not from a scroll handle's `bounds()`: handle bounds are the *previous* frame's layout, so a grid whose column count comes from them reflows a frame behind the drag and the cards visibly trail the cursor. `ui::LiveWidth` bridges the two — it remembers the gap between the viewport and the last measured element (sidebar, padding, an open panel, none of which change width while the window does) and subtracts it from the current viewport, so `ui::grid_columns` reflows on the same frame; chrome that *does* change width is picked up a frame later, exactly as before. The album and artist grids both use it. The player bar's flanking columns (`player_bar::side_width`) shrink together below ~1060px so the transport keeps its room and stays centred — fixed columns pushed the volume block off a narrow window's edge. `AlbumsView` also keeps one shared `Rc` of playlist ids for the cards' context menu (`sync_menu_playlists`), since collecting it per visible card per frame is a resize's worth of allocations for a menu that is usually closed.

The **sidebar folds** to a 52px icon rail (`SidebarModel::collapsed`, `SidebarAction::ToggleSidebar`, Ctrl/Cmd+B or the `PanelLeft*` handle — a plain muted icon like every other row, not a themed `Button`, and expanded it rides the first row that already exists (the Libraries header, or the Albums nav row — the first section in the rail; `SIDEBAR_SECTIONS` in `sidebar.rs` mirrors that order for vi-mode cycling and must be kept in step with it, and `sidebar_targets` builds the full walk from it) rather than spending a line of its own; only the collapsed rail gives it a row): labels go and the nav sections and the refresh/settings rows stay as icons with tooltips carrying the text they lost (including the refresh stage label, the only sign that job is moving). The **library switcher and the playlist list become dropdowns** rather than disappearing: each is an icon (`icons::LIBRARY` / `icons::LIST_MUSIC`) opening a `Popover` holding the very rows the expanded sidebar draws — `sidebar::library_row` and `sidebar::playlist_row` are shared by both so the two cannot drift apart. They sit where their expanded counterparts do (the switcher above the nav rows and under the same `libraries.len() > 1` condition, the playlists under the divider), and differ only in what happens after a pick, which is the `AfterPick` hook: a library toggles its checkbox and leaves the menu open since selecting several is the point, while opening a playlist is a navigation and closes it. Dismissal goes through the popover's own entity — a row's click handler is handed an `&mut App`, which cannot dismiss anything on its own. `Settings::sidebar_collapsed` persists the user's choice; `RootView::apply_orientation` — called at the top of `render` — folds it on its own when the window turns **portrait** (`height > width`) and restores the persisted value when it turns landscape again. Only the *transition* acts: applying the rule every frame would re-fold the sidebar the instant a user unfolded it in a portrait window, and a landscape start leaves the persisted value alone rather than forcing the sidebar open. A zero-sized viewport (a frame laid out before the window has one) is ignored, since it would read as landscape and burn the first transition. `LiveWidth` picks the new content width up a frame after a fold, like any other chrome that changes width.

The fullscreen player is the one view with no natural reflow, so `fullscreen_player::Layout::resolve` (pure, unit-tested) sizes it: cover, info card, side panel, the optional volume column and the vertical padding all come out of the window's width and height, and a **squarish** window — anything up to `STACK_MAX_ASPECT` (1.4) wide for its height, which takes in every portrait window as well as square, 5:4 and 4:3 — or one too narrow to hold cover and card side by side, stacks the cover above the card in one column instead (`stacks`, also what `CardDensity::for_window` estimates the card's width from). The row is for **widescreen**, where height is the scarce thing; a 4:3 has the height to carry the cover above the card and spending it on a row leaves a band of empty window under both columns. A *landscape* window has to earn the column, though: a short 4:3 has no height to put anything above anything, and the column comes back with a sliver of a cover where the row would draw one twice the size beside the card — so a landscape stack whose cover does not clear `CARD_MIN + ART_LEAD` goes back to the row. The floor is the card's *minimum*, not the card it got, since with a panel beside it the card is as wide as the panel leaves and is not competing with the cover for width. Portrait keeps the column either way. **Stacking the cover is not the same as stacking everything**: `Layout::panel_beside` puts an open panel *beside* the card under the cover wherever the content width holds `CARD_MIN + GAP` and the panel's own width — a 4:3 or 16:10 window turned on its side has width to spare, and the old single column drew the panel at the *card's* width (itself a share of the cover's), which left a gutter down each side of the window and took the panel's height out of the cover for nothing. There the card's width comes from what the panel leaves rather than from the cover, the cover is sized as if no panel were open, and the panel takes whatever height the cover does not want (so the row is taller than the card, and the card centres in it). It is derived, not a setting: it only engages where the width is already there. It was previously built from constants adding up to ~1300x620 of window, and the overlay does not scroll, so anything smaller simply lost what fell past the edge.

A window with room to spare goes the other way: `ART_MAX`/`ART_MAX_STACKED` are what a window that only just holds the overlay draws, and past them the cover grows with the window (`roomy_art_cap` / `stacked_art_cap`) rather than sitting as a fixed square in the middle of an empty page. **How far it grows is `Settings::fullscreen_cover`** (`config::FullscreenCoverSize`, Settings → Fullscreen → *Cover size*, passed into `Layout::resolve`): each size is a share of the room *and* a ceiling, since a ceiling alone leaves every size identical on a 1080p screen where the share is what the cover actually hits. `Fixed` is a share and ceiling of zero, which the clamp lifts back to `ART_MAX`/`ART_MAX_STACKED` — that is what "disabled" means here, and it is why the setting is a size rather than a switch: a window with no room to spare draws the same cover at every size. Beside the card it grows only into width the card does not want (`free - CARD_MAX`): taking it out of the card instead would push it toward `CARD_MIN` and cost the toggles their labels, a trade a big window never has to make. Stacked, the limit is a share of the content width, since there the column has height to spare.

The **queue panel** is a `uniform_list` of `QUEUE_ROW_H` rows drawn at a whole number of them (`queue_visible_rows` over the room `panel_max_h` gives it, `QUEUE_CHROME_H` for its header and padding) — a panel sized to the room it has ends mid-row, which reads as a rendering fault rather than as a list that carries on. `sync_queue_scroll` follows the playing track from `render` (the list only exists while the panel is open, and it needs `layout.panel_max_h`, so the call sits right after `Layout::resolve`); `queue_followed` means only a *change* of position scrolls, so a user reading down the queue is not dragged back, and closing the panel clears it so reopening re-centres. It scrolls to the row `visible / 2` above the track with `ScrollStrategy::Top`, **not** to the track with `Center`: `Top` lands the offset on a row boundary, and centring on the track itself leaves half a row at each edge — exactly what the row-snapped height is there to avoid.

The **lyrics panel** is set like a lyrics sheet rather than like the queue beside it: `FontWeight::BLACK` throughout (a face that stops at 700 is matched back to it, so asking for the heaviest costs nothing where there is none), `LYRIC_REM` (1.25) **growing** to `LYRIC_REM_ACTIVE` (1.5) on the line being sung, and the rest falling away from it by distance (`line_emphasis`, pure and unit-tested, over the `LYRIC_DIM` tiers — symmetric, so a verse already past is no more present than one still coming, and flat at the nearest tier for an intro or an unsynced document, neither of which has a line to be on and both of which would otherwise read as the panel being switched off). The reference look carries that distance as a **blur** as much as a fade; gpui has no element blur — its only `blur_radius` is on a `BoxShadow` and `with_transformation` is svg-only — so opacity carries the whole falloff, which is why it drops further than a blurred sheet would need. The move between two lines is a **handover, animated from both ends** over `LYRIC_GROW_MS` (420): the incoming line grows and brightens while the line being left (`lyrics_prev`, recorded in `sync_lyrics_scroll` when the active index changes) runs the same interpolation backwards. Animating only the incoming one — which is what it did first — leaves the outgoing line back at its resting size on the first frame of the transition, and the pair reads as the new line shoving the old rather than as the two trading places. Each direction carries **its own element id** (`fs-lyric-in-{ix}` / `fs-lyric-out-{ix}`): the id is the line's index so the animation replays as the highlight steps rather than running once per song, and the direction is in it because gpui drops the state behind an id that goes unrendered — which is what rewinds the clock, where one id per line would leave the shrink holding the grow's finished state. The easing is `ease_in_out`, not the `ease_out_quint` the rest of the app's transitions use: quint is 90% done in the first 40% of its duration, which is right for something appearing and wrong for two lines the eye is following at once, where a near-stationary tail reads as a jump however long the duration is. The growth itself is a real, continuous scale rather than a step between two size classes — `with_animation`'s animator runs inside `request_layout` and `Styled::text_size` takes any length, so interpolating the size is the nearest gpui gets to the reference look's `transform: scale`, there being no transform on a div at all. It costs the lines under it a few pixels of shift, which `sync_lyrics_scroll` takes back out on the next frame. What it must *not* cost is the line rewrapping halfway through: every line is laid out in `lyric_wrap` (pure, unit-tested) of the panel's width — its own size over `LYRIC_REM_ACTIVE` — so a resting line at 1.25rem in 83% of the width breaks at exactly the words it will break at once grown to 1.5rem in all of it, since advance width and available width then scale together and the ratio deciding the breaks is constant across the whole interpolation. The cost is that a resting line wraps a word or two earlier than it needs to, paid on the right where the text is not; the alternative is the last word dropping to a row of its own mid-animation and shoving the rest of the sheet down. It is **wider than the queue** to pay for all of it (`PANEL_LYRICS_MIN/MAX/SHARE` against the queue's `PANEL_*`, picked in `Layout::resolve` off the open panel rather than off a bool): at the queue's width that type wraps most lines in half, and a verse broken over twice as many rows is harder to follow than one whose lines sit where the writer put them. It fetches on open and on every song change (`maybe_fetch_lyrics`). It asks `getLyricsBySongId` and only falls back to classic `getLyrics` when that yields nothing, and it asks the server nothing at all for a **local** track — its id is the scanner's, not the server's, so the request can only ever miss. A local track reads **its own file** instead (`lyrics::from_file`, on the blocking pool since it opens and parses one): the sidecar `.lrc` beside it and its `LYRICS` tag, which is exactly what the server's scan collects for everything else, done for the files no server has ever seen. Both sources are returned and `best_lyrics` picks, so a timed sidecar wins over a plain tag; either may itself be LRC (some taggers write synced lyrics straight into the tag), so both go through the same timed-or-plain test rather than the sidecar being assumed to be the timed one. It is read **on demand, not at scan time** — editing an `.lrc` then shows up on the next open rather than the next scan, and a library's worth of lyric text stays out of `music.db`, which is rewritten far more often than it is read for this. The sidecar is decoded strictly as UTF-8 (a legacy codepage would come back as mojibake with working timings, and skipping it is what lets the online lookup have a go), with a leading BOM stripped or the first line's stamp is not at the start of the line and the whole document parses as untimed. `best_lyrics` (pure, unit-tested) picks one of the documents on offer: **synced wins**, since it is the same text with timings attached, and a document of nothing but blank lines is dropped so it reads as "no lyrics found" rather than as an empty panel.

A **timed** document is then followed line by line. `active_line` (pure, unit-tested) is the last line whose start has passed — `None` before the first one, since an intro has no line to light, and `None` for an untimed document, whose lines carry no start at all; it is a scan rather than a binary search because the list is a few dozen lines, it is consulted twice a second, and a server-supplied document is not guaranteed to be in order. The document's `offset` is **added** (OpenSubsonic defines it as the offset to *apply*), which is why `lyrics::parse_lrc` flips the sign of an LRC `[offset:]` tag — LRC's `+` means "show these earlier" — so both sources arrive in one convention. **A timed line is also a seek target**: clicking one moves the playhead to `lyric_seek_target` (pure, unit-tested), which is `active_line`'s comparison run backwards — the same `offset` applied in the same sense, or a click would land at a point that lights a *different* line than the one clicked, and the round trip is what the test asserts. A line with no start is inert and gets no pointer cursor, since an untimed sheet has no points to seek to. The click notifies the player rather than leaning on the per-frame repaint, which only runs while audio is moving — a line clicked on a paused track has to light too — and `PlayerState::seek` now writes the destination into `position` before handing it to the engine, so the lit line and the seek bar both move on the click instead of half a tick later (the engine's next tick reports that same destination anyway while a seek is in flight, and a seek that lands short or is dropped is corrected by the first tick after it; the restored-position path already did this). The lit line is `theme().primary` like every other playing-track mark, and only a timed document dims the rest: with no line to be on, a greyed-out page reads as the panel being switched off. The colour travels with the size and the fade rather than stepping — `lyric_color` (pure, unit-tested) mixes `foreground` and `primary` inside the same animators, one direction each. gpui has no colour interpolation; `Hsla::blend` is alpha compositing, but compositing the lit colour over the resting one at alpha `t` *is* the mix, and it runs through `Rgba`, so it takes the short way between two colours rather than the long way round the hue wheel that lerping H would. Both endpoints are exact (`blend` returns `other` at alpha 1 and `self` at 0), which matters because a lit line left a shade off `primary` is a sheet where no two lines are quite the same colour; the result keeps the resting alpha, since the line's own fade is the element's `opacity` and folding it in here would apply it twice. `sync_lyrics_scroll` keeps it on screen, called from `render` for the same reason `sync_queue_scroll` is — a `ScrollHandle`'s child bounds are the *last* paint's, so an offset computed from an event places the line the panel has since moved past, and setting it here (before the tree is built) is what makes this frame paint at it, where a `window.refresh()` would be a no-op mid-draw. The offset is **computed** rather than left to `scroll_to_item`, whose only strategies are "first visible" and "at the top": the line wants to sit `LYRICS_LEAD` (0.35) down the panel with what came before it still readable, and the lines wrap, so a lead counted in rows is not a lead in pixels. Child bounds are the unscrolled layout and the painted position is `child.top() + offset.y`, so the offset falls straight out of that; it is clamped to `[-max_offset, 0]` or the last verse is dragged past the end of the list. The lines are the scrolling element's **own children** rather than a column inside it, since a `ScrollHandle` only records what it tracks directly. `lyrics_followed` gates the scroll so only a *change* of line moves the list — between two lines a user reading ahead is left alone — and it is cleared by a panel toggle and by a song change; a frame whose child bounds are still empty (the list has not been painted yet) leaves it alone rather than marking the line done, so the next position tick retries. The travel is **eased**, over the same `LYRIC_GROW_MS` and curve as the lines' own handover: a `ScrollHandle` has no animated scroll and `set_offset` is a jump, and the transition is judged as one movement — the type easing gently while the sheet it is set on teleports underneath is the clunk, however careful the type animation is. `lyrics_scroll_anim` holds where the list was when the highlight moved and when it moved, and each frame eases from there toward a target **recomputed from the live child bounds**, which is what keeps the travel honest while the lines either side of it are still changing size. Easing from a recorded start rather than stepping off the current offset is what makes the duration the duration and not a function of how many frames landed; `lyrics_followed` is only set once `t` reaches 1, so an unfinished travel runs again next frame. A highlight that moves *again* mid-travel resets it rather than continuing — the old start offset and clock belong to the line before last, and easing toward a new target off those covers the remaining distance in whatever is left of the old duration, i.e. snaps, at exactly the moment (two lines in quick succession) the movement is most visible. `lyrics_following` therefore counts a travel in flight as well as audio moving, since this scroll is driven from `render` rather than by gpui's animation element, which asks for its own frames. **The highlight does not run at the engine's tick rate.** 500ms is fine for a seek bar and plainly late against words being sung, so `PlayerState::smooth_position` fills the gap in from the wall clock — `position` plus the time since the tick that set it (`position_at`, updated by `set_position`, which every assignment to `position` goes through). `smoothed` is pure and unit-tested: it advances only while `playing && !buffering` (the tick reports the *destination* during a seek, and a clock on top of that would race past a track that has not moved yet), caps the fill-in at `SMOOTH_MAX` (1s, two ticks — past that a tick did not merely arrive late, it is not coming, and the clock would be guessing), and clamps to the track duration. `position` itself stays a number somebody asked for — the engine's tick, or a seek's destination — never the wall clock's extrapolation of one, so nothing that persists or scrobbles it writes back a guess. Paying off needs frames: `lyrics_following` asks for `window.request_animation_frame()` per frame, and only for a **timed** document in an open panel with audio actually moving (or a scroll still travelling) — an untimed one has no line to light, and every other state is served by the position tick bringing the overlay back anyway.

The panel header carries a **source badge** (`LyricsSource`, `Library` / `LRCLIB`, with a tooltip spelling the distinction out) because the two paths do not mean the same thing: a library hit is the file's own words and is there offline forever, while an online hit is someone else's transcription of a track the library has nothing for — the one to doubt when the timings drift or the words belong to a different recording. `lyrics_source` is `Some` exactly when `lyrics` is, so a badge never appears beside "Loading…" or "No lyrics found", which would be naming the source of nothing. A **local** file draws `Library` for its own sidecar or tag and `LRCLIB` for anything else — it never reaches the server, but its own words are still its own words, which is what the badge is saying.

Everything neither the server nor the file itself has falls through to `services/lyrics::fetch`, behind `Settings::online_lyrics` (Settings → Library → *Fetch missing lyrics online*, **on** by default): a lookup on [LRCLIB](https://lrclib.net), the same community database `syncedlyrics` reaches for first — free, no key, and it answers with an LRC document when it has one, so the fallback routinely comes back *timed* where the tag-scraped copy is not. Two requests in order: `/api/get` (artist + title + album + duration, matched on all four) when the song carries enough metadata to ask, then `/api/search`, whose candidates `best` ranks — hits with nothing to show are filtered out **before** ranking so it cannot crown one the panel would then find empty, then length within `DURATION_TOLERANCE` (a different recording's timings drift out of step within a verse) over having timings at all; `min_by_key` on a reversed key rather than `max_by_key`, which returns the *last* of several equal maxima and would throw LRCLIB's own relevance order away. A 404 is `Ok(None)`, not an error — only a real answer is worth caching, and only the caller can tell the two apart. `parse_lrc` (pure, unit-tested) handles `[mm:ss]`/`[mm:ss.xx]`/`[mm:ss.xxx]`, several stamps on one line (a chorus written once per repeat becomes one line each), keeps `[offset:]` and drops the rest of the header; an untimed line inside a synced document is dropped rather than kept, since it is the header's leftovers and a line the panel cannot place is worse than one it does not have. Answers are cached in `config::lyrics_cache_dir()` under a **hash** of artist/title/album/duration (the fields joined run past what a filename holds, and `config::sanitize` flattens every non-alphanumeric byte, so two songs can collide). Misses are cached too — otherwise every reopen re-asks for a song nobody has — but only for `MISS_TTL` (7 days), since the database grows. The request is only ever made with the panel open, which is what keeps the feature from being a background phone-home.

Order of sacrifice, all of it verified against the running app rather than reasoned about: the volume column goes first (the player bar has one), then the cover shrinks; with a panel open in a window too tight for all three columns the *cover* is dropped and the card keeps the panel, since the panel was asked for and the cover was not; and in a window too short for a cover worth drawing at all (`ART_MIN`) it goes entirely.

The card is the one piece with a height floor and no way to scale, so it gives ground in stages — `CardDensity`, and **spacing goes before content**: `Tight` is the same card with its padding and row gaps pulled in, and only `Compact` (a window too short for even that) drops the album and stream-info lines. Its height depends on its *width* — below `INFO_ONE_LINE_MIN` the stream-info line wraps and the card is a row taller — while its width falls out of the height left over, so both branches lay themselves out twice: the column re-places once the card's real width is known, and the row steps down a density if the form picked from the window alone came out too tall. The stacked layout uses `Tight` to free height for the cover, never `Compact` — a tall window has room for the track's details, and hiding them there was a bug, not a trade. Inside the card the rows carry their own limits: `CARD_MIN` is what the five transport buttons need inside the card's padding, the queue/visualizer/lyrics buttons drop their labels below `TOGGLE_LABEL_MIN` (labelled, they need ~370px of row), and those rows plus the stream-info line `flex_wrap` so a miscalculation wraps instead of clipping.

In the **stacked** layout the cover leads: it is capped at `ART_MAX_STACKED` rather than the side-by-side `ART_MAX` (it has the whole width to itself there) and the card is drawn at `CARD_STACKED_SHARE` of it, floored at `CARD_MIN`, so the column reads as a cover with its controls under it rather than two equal blocks. Where the full card would leave the cover no lead (`ART_LEAD`), the column is laid out again with the *tight* card — spacing, not content — and the taller cover wins.

A scrolling wrapper is the last resort under all of that, and its inner column takes `min_h(px(window height))` — **not** a percentage: a percentage resolves against the scroll container's content, which is that column itself, so it collapses to the content height and the vertical centring is silently lost (the overlay renders top-aligned in every window).
  - **Vi-mode keyboard navigation** — when `settings.vi_mode` is ON, `root.rs`'s key handler routes to `handle_vi_key` and the legacy no-vi shortcuts (space/arrows/`[`/`]` = play/prev/next/nav) are dead; when OFF they work as before. Every content view implements the cursor protocol: a `vi_cursor: Option<usize>` field plus `vi_move(delta, window, cx)` (clamp + scroll focused item into view), `vi_activate(cx)` (Enter — open/play the focused item), `vi_clear(cx)` (hide cursor when the mode turns off). `root.rs` dispatches through `content_vi_move` / `content_vi_activate` / `content_vi_tab` — add every new `Content` variant to all three plus `vi_clear_cursors`. Focus styling lives in `ui/mod.rs` and every view goes through the same door, `with_focus_cursor(id, el, focused, glow, cx)`: the focused item always gets `border_color(primary)`, and the fill, the `focus_glow(cx)` BoxShadow and the 180 ms ease-out glow-in wrapper (per-item id, so it replays on each cursor jump) are added only when `glow` — i.e. `Settings::selection_glow`, off by default. `focus_glow`/`with_focus_animation` are private for that reason: a call site reaching past the helper would light up regardless of the setting. `anchor_scroll(Some(anchor))` + `ScrollAnchor::for_handle(handle)` scroll-into-view (which works for flex-wrap/nested rows) stays at the call sites, since it is per-view and must run whether the glow is on or not. The scroll itself must be triggered from **`render`, never from `vi_move`**: a `ScrollAnchor`'s origin is only as fresh as the last paint and `scroll_to` applies it at the next frame's start, so from a key handler it scrolls to the row the cursor just left — going up, the focused row lands one row above the viewport and the highlight vanishes. `ui::sync_focus_scroll(anchor, cursor, synced, window, cx)` centralises this (each view keeps a `vi_scroll_synced: Option<usize>` so only a real cursor move scrolls), and its `window.refresh()` is load-bearing: a bare scroll offset dirties nothing, so without it the correction would sit unpainted until some unrelated repaint. The albums grid is the exception — virtualized, so `vi_move` uses `UniformListScrollHandle::scroll_to_item(row, ScrollStrategy::Top)`; uniform_list's `ScrollStrategy` has only Top/Center/Bottom (no FirstVisible). In vi mode `[`/`]` cycle album filter tabs (`vi_tab`, via `select_tab` which persists `settings.album_sort`); in no-vi mode they are nav back/forward. `:` commands (`:newpl <name>`, `:pl add <name>`, `:pl list`, `:q`, `:help`) live in `execute_command`; `set_vi_status` shows transient feedback with a 4 s auto-clear.

A field with the keyboard wins over all of it: `RootView::vi_typing` is passed into `handle_vi_normal`/`handle_vi_insert`, which then **return without calling `cx.stop_propagation()`** — gpui only inserts text for a keystroke nothing else claimed, so swallowing space was what typed a space into the search box and started playback instead. Escape is the one key still handled, since dismissing the field is how the shortcuts come back. In insert mode the test is "focus is not my own handle". Normal mode cannot use that — gpui-component's buttons are focusable and gpui focuses anything with a tracked handle on mouse-down, so it would read as "typing" from the first button click onwards and kill j/k for the session — so it asks each field instead: the root's own inputs, `SearchBar::is_typing`, `PlayerBar::is_typing`, and `content_typing` for the three views that have a field (Settings, Radio, Playlist). A new text field anywhere needs an `is_typing` and a line in one of those.

The sidebar's own walk (`sidebar_targets`) includes the playlists **in both shapes**. Folded there are no playlist rows, so the rail's dropdown stands in for them: `RootView::rail_playlists_open` is the state, the `Popover` is driven from it (`.open(..)` + `.on_open_change(..)` — `open` alone is reverted by the next render), `sync_rail_playlists` opens it while the cursor is inside the playlist range and closes it on the way out, and activating a playlist, unfolding the sidebar or leaving vi mode close it too.

`recent.rs` rows are laid out inside a `uniform_list`, which sizes items to their content — so each row is explicitly `w_full()`, or the album and duration columns land at a different x on every line. It observes `PlayerState`, which calls `cx.notify()` on **every** event including `Event::Position` — so anything it does per notify or per render happens several times a second for as long as the page is open. It therefore gates on a cheap `signature` (list length + head song id, plus whether a client has appeared) before rebuilding, holds a pre-formatted `Row` model instead of re-deriving strings and cloning `Song`s per frame, and draws through `uniform_list`. Any future view that observes the player needs the same treatment.

`RootView` **retains the albums, artists and recent view entities** across navigation (`albums_view` / `artists_view` / `recent_view`) instead of rebuilding them per visit, which refetched the whole listing and reset scroll on every tab switch. They're subscribed to only on first construction (a second subscribe would stack handlers) and dropped by `invalidate_catalog_views` on **disconnect** and library-selection changes — they never reload on their own. A selection change only *re-navigates* when one of those listings is actually showing (`on_catalog_page`, shared with the refresh-complete path): `self.section` survives into the detail pages opened from it, so navigating unconditionally threw the user off an artist page and back to the grid on every checkbox tick. A detail page is updated in place instead (`reload_content_libraries` → `ArtistDetailView::reload_libraries`), which is the artist page alone — it is the only one the selection reaches, since `getArtist` takes no `musicFolderId` and the filtering is client-side. Its "Appears on" section refilters out of the cache immediately while the discography waits for the `getArtist` round trip; the old albums stay up meanwhile, because `keep_selected_libraries` can narrow the list it already has but never widen it. On *connect* they're kept and handed the client through `resume_catalog_views` → each view's `client_ready`, because a rebuild there would blank the covers and reset the scroll of the grid the user is already looking at.

Startup order matters: `RootView::new` opens the default page itself (`open_default_page`, via `cx.defer_in`) rather than waiting for the session observer. The observer only fires when the connect *resolves*, so leaving it to do the first navigation left the window empty for a whole network round-trip even though the cached catalog was ready to paint. It stays wired into the observer too, for the pages that only become reachable later.
  - `ui/visualizer.rs` — the 3D audio visualizer behind the fullscreen overlay. gpui exposes no shaders, so scenes are projected in software (world space → perspective divide → `gpui::canvas` + `paint_path`/`paint_quad`) and drawn back-to-front, since there is no depth buffer. Eight scenes (`Scene`): `Terrain` (scrolling spectrum landscape), `Tunnel` (rings receding to a vanishing point), `Sphere` (rotating Fibonacci point cloud), `Scope` (polar oscilloscope — the **only** scene drawing the time domain: `scope_trace` triggers on a rising zero crossing, since an untriggered trace slides by a random phase each frame, and samples directly at `SCOPE_STRIDE` rather than reducing buckets to peaks, which would draw the envelope and stop the ring crossing its own baseline; past traces are kept in a `scope` deque and drawn as outward-drifting echoes, and a starved tap pushes a flat trace so the trails drain; a faint baseline circle gives the displacement something to be read against, and `hot_runs` picks the stretches swinging within `SCOPE_HOT_REL` of *this trace's own* peak and redraws them thick and near-white — an absolute threshold puts the whole waveform over it on a loud passage and the bloom disappears exactly when it should be strongest), `Bloom` (kaleidoscope mandala in screen space — perspective would break the radial symmetry that is the whole point; per-layer petal counts (`BLOOM_LAYER_SECTORS`, deliberately not dividing each other — layers sharing a count lock into one rigid figure however they rotate) with odd sectors reading the spectrum backwards to mirror, a `sin(πu)` lobe window so petals return to the inner circle instead of merging into a lumpy ring, counter-rotating translucent layers, a bass-driven hub closing the hole the inner radius leaves, and beat spokes drawn *under* the petals and stopped short of them), `Warp` (starfield where each star is drawn as the segment it is about to travel, so speed reads as streak length — the shared per-frame `warp_speed` rides energy plus the beat flash; the field rolls slowly (`WARP_ROLL`) so it reads as flight rather than a zoom, and stars fade out over `WARP_NEAR_FADE` before recycling instead of popping at the near plane), `Orb` (wireframe icosphere — bass inflates the radius, treble roughens it via 3D value noise along the normals; the mesh is generated once by `OrbMesh::new` and the whole wireframe is stroked as subpaths of a *single* path, since a thousand-odd separate tessellations per frame is not affordable), `Retro` (PlayStation-era look: deformed low-poly solids tumbling at the camera over a bass-reactive background — flat per-face shading, back-face culling, painter-sorted opaque faces, depth fog, and `SNAP`-quantised screen vertices for the era's jitter). `VisualizerMode` (in `config.rs`, cycled by the fullscreen player's button and persisted) is Off → **Auto** → the eight pinned scenes (`VisualizerMode::SCENES`, which the mini player's scene popover iterates — adding a scene there needs no UI change). In Auto the scene alternates on the music: `OnsetSwitcher` watches spectral flux (rises only, from the *raw* bands — the smoothed ones have the transients filed off) and switches on flux peaks in two stages, because flux peaks on the *run-up* (risers, snare rolls) and firing on the threshold crossing lands before the beat: the detection function is bass-weighted (`0.7·bass_flux + 0.3·flux`, `Onset::strength`), crossing `max(mean + 2.2σ, 2.5×mean)` of the last ~4s only **arms**, and the switch **commits** when the transient turns over with the low end held up 1.18× for 3 frames (a riser is a narrow sweep; the thing it leads into brings the kick back — and a kick rings for several frames where noise jitter lasts one). Every threshold needs its ratio floor as well as its sigma term: in steady passages the spread collapses toward zero and a sigma-only test fires on nothing at all, which then eats the next real drop via the hold. 9s hold, 45s backstop so ambient tracks still move. The next scene is picked at **random**, excluding the current one and the one before it — a fixed rotation is predictable after one pass, and an unconstrained pick repeats or ping-pongs. Changes cross-fade over 220ms (incoming rises fast so the cut lands on the beat). While a scene runs the overlay's big cover + info column stands down and a **floating mini player** (cover thumb, title/artist, transport, seek bar, and the scene picker: `Off` and `Auto` as buttons, every scene behind one `More` popover — a button per scene crowded the card and buried the two entries that are not scenes) floats over the scene instead — so the visualizer gets the whole window and its controls live in it. Queue/Lyrics panels and the optional volume slider belong to the normal layout and are not in the mini player. The mini player's slider button opens the **tuning card** (`VizKnob` in `fullscreen_player.rs`): sensitivity (band gain), smoothing (attack/release), reaction depth (`power`, how far the audio deforms each scene), motion speed, and the two Auto-only knobs (switch sensitivity, scene hold). It floats over the running scene on purpose — every one of these is judged by eye — and writes `Settings::visualizer_tuning`, which `tick` re-reads each frame, so a drag retunes live. Defaults reproduce the untuned look exactly. Terrain rows widen with depth (`terrain_row_half`) so no row ever ends inside the window; a constant-width grid shrinks as 1/z and reads as a floating carpet. `Visualizer::tick` runs one FFT per frame; the fullscreen player calls `window.request_animation_frame()` while a scene is on, and nothing at all when it is off.
  - `ui/mod.rs` — shared helpers, theming included. **`ui::Reveal`** is the open/close clock for anything only mounted while it is open: `with_animation` runs only while its element is in the tree, so a panel dropped on close plays no exit at all, which is why the queue panel, the fullscreen side panel and the command palette all used to slide in and then blink out. The view calls `set(flag, reduced_motion)` from `render` against the bool that already owns the panel (a no-op unless that is a change, so the two cannot drift apart), then asks `visible` whether to draw at all, `openness` for the opacity and the fraction of any offset, and `settling` whether to `window.request_animation_frame()` — gpui only redraws on demand. Driving it from state rather than from a wrapper element is also what keeps nested animations alive, since gpui keys an animation's start instant on the whole ancestor element-id path (a wrapper swapped between an enter id and an exit id restarts everything underneath it). The easing is applied to the **travel**, not to the openness — `reveal_openness` is pure and unit-tested — because `ease_out_quint` spends 90% of its curve in the first 40% of its input, so reading it at a falling openness leaves a panel sitting still for half its exit and then vanishing; a reversal starts from where the travel had got to and its span is scaled by the distance left, or a panel toggled twice turns around at a crawl. `replay()` restarts the entrance from nothing, for a panel whose *contents* are swapped while it is open. Everything mounted behind a flag goes through it — the queue panel, the fullscreen side panel and tuning card, the command palette, the new-playlist dialog, the vi-mode help overlay and the `:` command bar — each fading *and* moving, since a fade alone on a strip or a card reads as a flicker. A modal is also handed the flag itself alongside the travel (`active`): it is still on screen for the length of its exit, so its buttons' `on_click` and the command bar's `capture_key_down` are attached only while it is open, or a click landing on "Create" after Cancel would create the playlist anyway. Fullscreen Queue ↔ Lyrics is a **swap, not a re-open**: the outgoing panel leaves first and `replay()` fires when the travel reaches 0, since replacing the contents where they stand cuts the outgoing panel off mid-travel. Two call sites need care: the fullscreen player keeps `panel_drawn` — the panel on screen, which lags `panel` by the exit — and sizes `Layout::resolve` from *that*, or the cover grows into the panel's room while the panel is still in it; and the palette's `Reveal` lives in `SearchBar` but is set from `open_palette`/`dismiss` rather than from `render`, because `RootView` draws the backdrop and reads it in its own render, which runs first. `dismiss` also stops clearing the query and its results — the box is still on screen for the length of its exit, and one that empties itself back to "Type to search…" on the way out reads as the search being lost rather than as the palette closing; `open_palette` resets all of it instead. `accent_from_cover_bytes` (the Adaptive theme's cover-derived accent) returns `None` **only** when the image fails to decode: it tries a vivid pass, then a relaxed one with no lightness penalty, then a neutral accent built from the cover's mean lightness. Very dark and very bright covers failed the vivid pass outright, and the accent then silently stayed on the *previous* album's colour. `RootView::maybe_update_adaptive_accent` matches: it resolves local tracks' art straight off disk (no client, no server cover id) and clears its remembered art key when extraction fails, so the next player notify retries instead of pinning the old colour. **Applying it once is not enough**: `Theme::change` (every `apply_theme`, i.e. any theme pick in Settings) resets every colour to the mode's defaults, whose dark `primary` is `#fafafa` — so a wipe reads as "the accent stopped working", and none of the function's short-circuits would have re-derived it. `restore_adaptive_accent` therefore re-applies the last extracted accent whenever `theme().primary` has drifted off it, before any of them, and `SettingsView::set_theme` notifies the session so that pass actually happens (a paused player emits no events to ride on). The root also derives the accent once from `cx.defer_in` at construction, since the queue is restored inside the player's own constructor and no notify reaches the observer. The remembered art key is `Option<Option<String>>`: the outer `None` means unresolved-retry, `Some(None)` a track that genuinely has no cover — collapsed into one, a coverless track matched the initial state and short-circuited forever. A coverless or unreachable cover keeps the previous accent rather than falling back to the default. The global accent always follows the **playing track** — the chrome (sidebar, player bar, sliders, fullscreen) belongs to playback. `Settings::adaptive_from_page` instead lets an album page tint *itself* from its own cover: gpui-component's `Theme` is a single global with no scoping, so the page paints its own accent surfaces (`ui::accent_button` builds a `ButtonCustomVariant` matching the primary button, `ui::page_tint` the header wash) rather than swapping the theme. The header wash is its own setting, `adaptive_page_gradient`, off by default and gated on `adaptive_from_page` — the accented controls are the quiet half of the feature, the gradient the loud one. Both detail views hold `accent`/`accent_for` and call `refresh_accent` from `load`, the cover fetch *and* `render` — the render call is what makes toggling the setting tint the page already open, and it no-ops once that cover has been decoded. The playing-track row highlight deliberately stays on `theme().primary`: it marks playback, which is what the rest of the app is coloured by. Sliders are the reason the accent is page-local rather than global-with-the-player-pinned — gpui-component's `Slider` has no colour override, so a global flip would strand the volume slider on the page's colour inside a track-coloured bar.
  - `ui/settings.rs` — the page lays *itself* out, with no setting behind it: one scrolling column of section cards with a quick-nav pill strip, or a centred **asymmetric grid** of the same cards where the window can hold the whole page at once. `compact_grid` (pure, unit-tested) is both the plan and the decision — it returns nothing when the window wants the column, and `render` derives `compact` from `grid.is_empty()`. `compact_columns` returns a count only when at least **two** columns fit the width and the tallest fits the height: one column is not a grid (it is the scrolling page with its captions taken away, a worse page rather than a denser one), and a grid that does not fit has given up the one thing it is for. Of the counts that fit, the one closest to **square**, scored as `|ln(width/height)|` — the widest count the width allows leaves every card in the top strip of a tall window, and the fewest that fit leaves one column down the middle of a wide one. Width sets the ceiling: columns of `COMPACT_COL_MIN` (380, what a switch's one-line label needs before it pushes out through the card) that fit in it, capped at `COMPACT_COL_MAX` and at one per section. The page keeps its order: `split_runs` cuts the sections into **contiguous** runs — one per column, balanced by binary-searching the height cap a left-to-right greedy can meet — so reading down a column and on to the next gives the sections in the order the scrolling page has them (packing them by size balances better and shuffles the page). Columns are drawn at `COMPACT_COL_TARGET` (460) each and the grid is centred in whatever is left rather than stretched across it; each column's width is nudged in proportion to what it carries, clamped around an even split (the tall column is the one whose rows wrap, so the extra width buys height back) and dropped back to an even split if that would take any column under the label floor. Heights come from the `COMPACT_ROW_H`/`COMPACT_CARD_H` model over the `COMPACT_SECTIONS` weights, which matched the running page to within 2%; the table is hand-kept, keyed by document order and debug-asserted in `section()`, since a card's real height is only known after it is built and the column widths are needed before. What pays for the grid's height is the captions: `note()` returns a `hidden()` element there (`display: none`, which taffy drops from the flex items *and its gaps* — an empty child would leave its gap behind), and `vi_library_task` drops its description the same way. They come back with the scrolling column. The quick-nav pills are not drawn in the grid (nothing to scroll to) and `scroll_to_section`/`current_section` bail out, because the scroll body's children are columns there rather than sections — `ScrollHandle::bounds_for_item` is measuring the wrong thing. The body keeps its scroll as a last resort. The vi cursor is unaffected by either layout: captions are not controls, so the control order is identical. The width and height the choice hangs off only exist **after** a frame has been laid out, and the measurement landing dirties nothing — so the unmeasured first frame's guess stayed up until something else happened to repaint the view: 333ms in the running app, and with nothing playing, until the next input. `render` asks for the frame that has the measurement itself via `window.request_animation_frame()` — **not** `Window::refresh`, which is a no-op while the window is drawing, i.e. exactly when a view renders — and paints that first frame's body at `opacity(0.)`, since it is laid out only to produce the measurement and which layout the window wants is not known yet.
  - `errors.rs` — the one place a failure becomes text. `error_text` prefers a `subsonic::Error`'s own `user_message()` (keeping any anyhow context the app added in front of it) and scrubs query strings out of anything else via `playback::scrub_urls`; `ErrorNote { text, retryable }` is what the views hold, and `ui::error_banner` draws it with a **Retry** button when `retryable`. The button only appears for failures where trying again could work: the catalog views are retained across navigation, so before this the only way past a failed listing was a restart — navigating away and back re-rendered the same dead page without re-requesting. `playback_error` does the same job for the engine's messages, which come from rodio, symphonia and reqwest and are written for a log: it names the track that failed and says why in words. A run of `MAX_FAILED_STREAK` failures says so explicitly, since there the queue has *stopped* rather than skipped on.
  - `config.rs` — settings TOML via `directories::ProjectDirs`; password in OS keyring (`keyring` crate), plaintext-in-settings fallback only when keyring fails. Also owns the cache dirs (artwork, waveform peaks), persisted UI prefs (`default_page`, `album_sort`, selected `library_ids` — legacy single `library_id` is migrated on load), and `local_music_dirs: Vec<PathBuf>` for local file scanning.

### Async pattern (used everywhere in the app crate)

```rust
cx.spawn(async move |this, cx| {
    let data = runtime::spawn_io(async move { client.some_call().await.map_err(anyhow::Error::from) }).await;
    let _ = this.update(cx, |view, cx| { /* apply */ cx.notify(); });
}).detach();
```

Never block gpui's executor with IO; never share locks with UI state — entities are mutated only via `update`.

## Pinning & toolchain notes

- **gpui `0.2.2` + gpui-component `0.5.1` are a matched crates.io pair** (gpui-component depends on `gpui ^0.2.2`). Do NOT bump one without the other; do NOT switch to git deps casually — gpui-component `main` tracks Zed `main` and churns. gpui types stay confined to `crates/app`.
- gpui is built with the `runtime_shaders` feature: required on machines with Command Line Tools only (no `xcrun metal`). Don't remove it.
- `[profile.dev.package.{gpui,gpui-macros,gpui-component}] opt-level = 2` — only the heavy gpui deps, not all workspace crates.
- rodio is built with `symphonia-all`. Its defaults only cover flac/mp3/aac-in-mp4/vorbis/wav, so raw streams of ALAC (m4a), aiff, mkv, caf or adpcm fail with "The format of the data has not been recognized" — rodio reports a missing *codec* as an unrecognized *format*. Covered by `plays_alac_m4a_stream` in `crates/playback/tests/engine_test.rs`. The codec itself is not the usual problem: symphonia decodes ALAC 16/24-bit, mono through 5.1, up to 192kHz, cover-art tracks and fragmented mp4. What fails is the **container being unreadable over HTTP** — `moov` after the audio plus a response the decoder cannot seek in. `m4a_without_content_length_reports_the_container` and `library_tracks_do_not_request_icy_metadata` cover both halves; both use a raw `TcpListener` server rather than wiremock, which always sets a `Content-Length` and so cannot express the failing case.
- **stream-download is a local fork** (`vendor/stream-download`, `[patch.crates-io]`, 0.24.4 with one patch): `Source::notify_if_position_reached`, factored out of the ordinary write path so the **prefetch** path uses it too. Upstream, a seek restarts the prefetch at the seek target and the prefetch writes never wake a reader waiting on a position — so the reader stays parked until some later *ordinary* write crosses it, which for a seek to the end of a file is after the whole file has downloaded. Every m4a whose `moov` index sits after the audio is exactly that: the decoder's first move is to seek to the index, so building the decoder cost a full download. Measured against a real Navidrome at **12.1s** on a 4.5MB AAC track, versus 0.85s patched — and `DECODE_TIMEOUT` is 12s, so a link slightly slower than that did not merely stall the album, it failed tracks with "timed out identifying the stream", and gapless was impossible because the *next* track's prefetch could not finish inside the current one either. `a_trailing_index_is_read_without_the_whole_download` covers it: the ALAC fixture with a 4MB `free` atom wedged between audio and index (a `free` atom is ignorable padding sitting after the audio, so every offset the index carries still points where it did) served by `slow_range_server`, asserting playback starts inside 3s where an unpatched build takes ~11s. Re-derive the patch by hand when bumping the version; it is ~20 lines in `src/source/mod.rs`.
- Edition 2024 across the workspace; let-chains are used (`if let … && …`).
- `souvlaki` (media keys / MPRIS) needs `dbus` on Linux; init is best-effort and `MediaKeys` degrades to a no-op if the backend is unavailable, so it never blocks startup.

## Testing conventions

- `subsonic`: wiremock integration tests in `tests/client_test.rs` — token/auth param assertions, envelope parsing from realistic Navidrome JSON, error-code mapping. Add a wiremock test for every new endpoint.
- `playback`: `tests/engine_test.rs` streams a generated in-memory WAV from a wiremock server through the full engine and asserts the event sequence; also tests local file playback via `plays_local_wav_to_completion` (temp WAV file) and `local_file_missing_errors` (non-existent path). `a_slow_seek_does_not_stop_the_engine_answering` needs a server wiremock cannot be: `slow_range_server` trickles the body after the first chunk and sits on every ranged request, which is the only way to make a seek take long enough for an engine that waits out the seek to be caught doing it; it also serves `a_trailing_index_is_read_without_the_whole_download`, which is why it takes the content type rather than always claiming to be a WAV. Self-skips when no audio device exists (CI).
- Manual smoke: demo.navidrome.org (user `demo`/`demo`) or `docker run deluan/navidrome`. Navidrome quirk: folder browsing is simulated — only use ID3 endpoints (`getArtists`/`getAlbum*`), never `getIndexes`/`getMusicDirectory`.
- Scrobbling is server-side: client only calls `/rest/scrobble` (`submission=false` on start, `true` at ≥50%/4min); Navidrome forwards to ListenBrainz/Last.fm itself.
